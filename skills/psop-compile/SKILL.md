# PSOP Compile v2

2026-11-06（Asia/Shanghai）。Compile 读取固定 DKP，管理样本、数据集、训练、模型和评测工件；不回写硬件事实。先读[共同装配语义](../../docs/architecture/assembly-interfaces.md)及[Compile 设计](../../docs/compile/compile-design.md)。

## 高优先级：装配判定与设计保真

**不能把刚性网格交集直接作为装配的否决条件，也不应为了消除交集就认定需要移动或修改原设计。** 监督与提示词遵循[共同判定规则](../../docs/architecture/assembly-judgment-policy.md)：几何交集、参考装配、操作资格和力学状态分列。刚性求交重叠、未建模变形或来源偏置不直接生成“不可装配／误装／设计错误”负例；消除交集后的姿态不自动作为唯一正确答案。

## 当前执行边界

真实图像生成、训练、权重加载与推理服务仍未接入，不存在可宣称成功的训练 CLI。共享装配查询输出是有限范围的候选／检查结果，不是训练执行或合格装配标签。用户要求运行时核对真实输入和执行器，缺项明确 unavailable，不虚构指标、模型或图片。

## 监督层次

分别组织 Feature／逻辑孔／有限开口／内腔／槽／实体锥销、可寻址安装位置、几何模式、参考观测、带功能依据的接口、参考安装映射、安装方案、局部状态及 Task 判断。Build 提供的标准双孔映射可作为该参考配置和声明范围内的孔位配对正例；保留用户说明、几何复核和工程验收各自来源，不把已知解扩大为唯一解。相向面、齐孔、source qpos0、已选孔 S、法向半空间和旧自动接口标签，均不能直接成为‘已紧固’正例；未列组合不自动成为负例。

按[共同一致性规则](../../docs/architecture/assembly-interfaces.md#9-规则绑定操作和显示的一致性)分别标注能力规则、具体绑定、操作方向／路径和实际状态。对应、进入侧、承座、尺寸、保持、活动归属和承载各自追溯证据，不因同一 Source 出现在审查中就视为全部结论有依据。多参与者作用链、同一特征的不同机制及部分成立状态保留原语义，不能压成“能装／不能装”单标签。

AB、CD、ABC、ABCD 是同一参数化方式可能的绑定，不复制成互斥接口类别。保留成员身份、选中子集、对端映射、连接件与统一构型。对称孔组保留等价标注或 Task 明确的方向差异，不把特征 ID 排序或唯一参考姿态作为真值。

八个安装孔位与四条共享孔道的身份映射进入监督血缘：入口侧不同不等于物理资源独立。训练／验证分组同时考虑底层孔道、来源网格及设备修订，避免把同一孔的两侧裁片拆到不同集合造成泄漏。渲染高亮不以拓扑支持三角面冒充孔口或连接作用区。

实体柱与孔按源壁及端面证据分别标注，不将 null 孔引用当成共享通道；已确认四位置但未知数量规则，不能生成“必须四选全”或“至少双孔”的监督标签。qpos0 相位不合、相邻轴线吻合分别限定于其测量配置，均不是不可安装或已经保持真值。

1.6 的 connection_reviews 与全对筛查是可审查的知识和缺项，不能把 review_required、包围范围交叠或未决方案标为连接成立。1.7 的 pin_hole_fits 保留共同配置、一一映射、有限插入和径向间隙，仅支持安装定位用途推断，保持与承载 unknown；参考两成员不是最少数量或允许子集。外侧共轴大洞用途未知，不作主接口或装饰监督。user_statement、project_inference、manufacturer_general 分别保留，旧 1.6 资格限定于冻结历史，已撤回的小柱功能标签不作用户确认真值。

supplemental_components 属于 synthetic／illustrative_unconfirmed，渲染及样本保留 usage 和实际可见性。reference_connector 仅为已有参考路径中的未绑定连接件；unverified_alternative 不进入当前保持角色，厂商轴心螺钉／压盖归此类、默认不显示。图像和参数不作真实设备 BOM、已安装紧固件或已固定正例，不能通过示意图循环证明实际使用。

1.10 的 installation_hypotheses 保存具体对端、机制和支持/反对证据，仍是有范围的 project_inference。investigation_records 的 investigated 只表示已执行所列检查，insufficient 明确保留缺证；两者都不是已接合、已保持或工程成功监督。几何截面、安装假设、安装定义、合格 Interface 和工程确认分别保留身份与数量。当前 Compile 没有执行器，新字段可以作为可追溯的研究上下文，不能声称已生成训练集或经过物理验证的标签。

几何轴线、孔口向量、操作方向和相机／爆炸变换不能共用方向标签。生成样本前核对声明操作与示意姿态的一致性；历史 1.7 标准双孔示意的已知方向缺陷及未经独立检查的方向不能进入安装指导真值。受影响样本隔离并追踪修订，未受影响的孔位对应证据不因此全部作废。某图形违背其声明路径只能标为该图形／假设的一致性失败，不能直接作为实物误装、机械不可能或所有替代装法失败的负例。

机械、工程、Task、完成和计算支持状态分列。部分路径保持、其余尚未进入、工程未批准和任务错误可以同时存在。合成夹具的规则与结果标明 synthetic，不借给 Microduck 填入未知功能或安装许可。

新的几何/关系/操作/力学字段与负例审查要求见[装配监督合同 /1](references/assembly-supervision-contract.md)。此合同不表示已接入训练或生成数据集。

## 工作流程

1. 固定工作区、设备知识版本、源材料、监督层次与目标任务。
2. 为部件检测、孔／接口识别、关系、方案建议和现场帮助分别说明输入、标签与评价；不为凑角色虚构模型运行。
3. 通过 Simulate 共用的场景／渲染底座提交有界生成计划，保留配置、相机、来源、检查能力与假设。
4. 审核候选和局部状态，按 CAD、孔组、装配／场景家族分组划分；同族多视角、对称映射、增强及相邻帧不得跨训练／测试泄漏。
5. 实际训练器接入后固定基座、环境、数据、参数和检查点，保存真实运行；模型测试固定实际可用版本与观察。
6. 失败与纠正经审核形成后续数据版本；基础功能和设备事实修订回到 Build 发布新 DKP。

隐藏状态、完整孔映射、标准步骤和求解答案只供标签与评测，最终模型只读真实运行环境可取得的观察。关系及帮助模型采用实际感知预测并覆盖误检／漏检；模型输出的安装建议继续由共享规则和执行链验证。

数据集、模型和评测独立版本化，引用知识、方案和观测的修订／摘要。旧 compile-profile、包内 App 和静态样例不作为当前发布物。

1.8 参考连接件的 insertion 保留外侧入口、头下基准、杆向、目标与有限壁段；finite_geometry=pass 只说明显式假设的图形一致，连续路径未评估、保持未知，不成为实物方向或装配完成标签。
