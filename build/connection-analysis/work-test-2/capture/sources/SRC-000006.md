# 操作与检查

本页为官方操作文档的中文摘选，软件依据为 `4861141fdc7c7acd253671acf5abdd55b77b779e`。只适用于已安装对应官方软件的机器人；不能据此确认社区改装硬件兼容。

## 适用硬件与通信条件

本页对应官方 alpha 控制配置：Radxa Zero 3W、15 个 XL330 系列舵机和 `imu_to_dxl v2` 身体姿态板。舵机与姿态板共用 `/dev/ttyS2`，速率为 `1 000 000 bit/s`，姿态板 ID 为 `200`。部件来源见 [设备说明](../01-设备信息/设备说明.md)，通信 ID 见 [关节表](../01-设备信息/关节名称与ID.md)。

默认快速同步读取使用指令 `0x8A`，要求 XL330 固件 **v46 或更新版本**，姿态板固件也必须支持该指令。持续出现 `bus read failed` 时应检查这些条件；不支持时执行 `sudo robotctl configure`，将 `[bus]` 下的 `fast_sync_read` 明确设置为 `false`，在机器人受到支撑且停止动作后按提示重启 `robotd` 再检查。删除或注释该配置不会关闭默认启用的快速读取。不能把“有串口”当作固件兼容。

尚未安装软件的开发板，使用 [官方开发板安装说明](https://github.com/pollen-robotics/microduck/blob/4861141fdc7c7acd253671acf5abdd55b77b779e/docs/robot/install-dev.md)与 [逐步安装说明](https://github.com/pollen-robotics/microduck/blob/4861141fdc7c7acd253671acf5abdd55b77b779e/docs/robot/install-by-hand.md)，完成对应软件环境后再按本页检查；其中开发密钥与开发版本设置不适用于普通交付机器。

## 1. 查看版本与设备状态

在机器人终端执行：

```bash
robotctl version
robotctl health
robotctl system info
```

`version` 对照已安装版本和正在运行的各服务版本；如不一致，先处理版本问题。`health` 汇总硬件和软件状态；不健康或无法访问机器人时返回非零退出码。但温度偏高等提示不一定影响退出码，因此仍需阅读完整报告。

查看运行中的目标值、测量值、限幅原因和电池状态：

```bash
robotctl monitor
```

需要保留原始状态流时：

```bash
robotctl monitor --json --hz 50 > run.jsonl
```

这些命令用于检查和记录，不代表机器人已完成实机验收。

## 2. 配对手柄

1. 让手柄进入配对模式。Xbox：短按电源键开机，再按顶部 Sync，直到指示灯快速闪烁；DualSense：同时按住 Create 和 PS，直到灯条闪烁；Pro Controller：按住顶部 Sync，直到指示灯往返闪动。
2. 在机器人终端执行：

```bash
sudo robotctl pad pair
robotctl pad status
```

3. 检查两项状态：手柄显示 `connected`，`padd` 显示 `active`。只看到蓝牙连接，不代表控制服务正常。

同时发现多个待配对手柄时，工具会拒绝猜测，可按它列出的真实地址指定手柄：

```bash
sudo robotctl pad pair <手柄蓝牙地址>
```

配对与信任完成后，手柄可在机器人重启后重新连接。不要把示例地址当成自己的设备地址。

## 3. 关节初始化与释放

初始化会移动所有关节，约 2 秒进入默认姿态。先将机器人放在适当支架上：

```bash
sudo robotctl robot init
```

手柄 Start 的默认行为：第一次按下开启舵机扭矩并进入默认姿态；第二次启动动作策略；此后在策略启停间切换。停止策略后仍保持关节支撑。

释放关节会使机器人失去支撑，先扶住机器人：

```bash
sudo robotctl robot relax --yes
```

这里的“释放关节”指关闭舵机扭矩，使关节不再主动支撑；不等于整机断电。停止动作策略后仍保持支撑，与释放关节不同。

## 4. 默认控制

| 操作 | 默认行为 |
| --- | --- |
| 左摇杆 | 行走模式下前后和横向移动 |
| 右摇杆 | 行走模式下转向 |
| Y／三角 | 切换头部控制；启用手柄 IMU 控制时行为有所变化 |
| B／圆圈 | 身体姿态控制 |
| A／叉 | 步行模式下向地面取物；轮滑模式下为蹲伏 |
| 方向键下 | 坐下与站立切换 |
| RT／LT | 两者都控制喙；RT 还触发鸭叫声，按住 LT 时还会发出“wheee”音效 |
| Select 短按后松开 | 释放关节，机器人会倒下，需扶住 |
| Select 长按约 2 秒 | 坐下、释放关节并关机 |

只有 A、X、LB、RB 和方向键下支持技能重绑定；Start、Y、B、Select 及模拟扳机不在此范围。LB／RB 是肩键，不是控制喙的扳机。执行前可查看当前绑定：

```bash
robotctl pad bindings
```

## 5. 更新与回退

先检查：

```bash
robotctl update status
robotctl update check daemon
```

需要更新时执行：

```bash
sudo robotctl update apply daemon
```

之后检查 `robotctl version` 和 `robotctl health`，确认正在运行的版本及设备状态。查看更新记录：

```bash
robotctl update log
robotctl update show
```

需要回退时，官方提供：

```bash
sudo robotctl update rollback daemon
```

回退后仍应重新检查版本与健康状态。软件升级成功不能替代机械配合、关节零位或功能验收。

## 6. 软件与传感器逐项检查

以下是依据官方命令输出整理的检查顺序，用于已有并正确装配的机器人。先在支架上检查，再按第 3 节初始化；检查结果应记录实际软件版本和输出。这里没有将检查通过等同于厂家整机验收。

| 顺序 | 操作 | 需要观察的结果与异常含义 |
| --- | --- | --- |
| 1. 版本 | `robotctl version` | 已安装版本与实际运行版本对应；不一致时先检查服务更新状态 |
| 2. 通信和循环 | `robotctl health`、`robotctl monitor` | 检查总线失败、循环停滞、限幅原因、实际频率及电池/温度提示；默认目标 50 Hz，不把默认值当作制造验收标准 |
| 3. 身体姿态 | `robotctl monitor` | 直立时投影重力约为 `[0, 0, -1]`；同时核对数据更新和 `orientation frozen` 等健康提示，冻结的旧数值不算有效测量 |
| 4. 头部测距 | 在 `robotctl monitor` 中按 `t` | 已装传感器时应有更新的 8×8 测距帧；`·` 为范围内无目标，`x` 为无法测量；`no sensor` 表示服务运行但传感器未应答，不能仅凭此判断是未装还是接线故障 |
| 5. 相机 | 在 `robotctl monitor` 中按 `c` | 取得当前画面；连接被拒绝先查 `mediad`，捕获超时查图像采集。画面可见不等于已完成相机标定 |
| 6. 声音、手柄 | `robotctl quack`；`robotctl pad status` | 前者检查叫声输出；后者同时确认 `connected` 与 `padd active`。播放成功不代表麦克风已检查 |

头部 BMI088 默认关闭采集；需要使用时执行 `sudo robotctl configure`，启用 `[head_imu] enabled` 并按提示重启 `tofd`。这不会把 HAT 的头部 IMU 变成 ID `200` 的身体姿态板；两者的接口见 [主控与传感器接口](../01-设备信息/设备说明.md#主控与传感器接口)。

## 7. 初始化与标定的区别

`robot init` 是按软件默认角度移动关节；替换舵机自动分配 ID 是通信配置。这两步都不能测出装配后的实际零位或证明机械限位正确。身体姿态芯片的自动陀螺仪偏置估计，也不等于整机传感器标定。

本包尚未取得完整的官方零位工装、装配公差、逐处紧固要求、线束布置、传感器标定步骤及出厂验收阈值，因此本页只提供上述有官方依据的操作和检查。官方相关工作状态见 [路线图](https://github.com/pollen-robotics/microduck/blob/4861141fdc7c7acd253671acf5abdd55b77b779e/docs/project/roadmap.md)。
