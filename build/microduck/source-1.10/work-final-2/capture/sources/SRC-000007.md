# 故障排查与舵机更换

依据官方软件文档 `4861141fdc7c7acd253671acf5abdd55b77b779e` 的中文整理。这是官方公开的局部排错与替换说明，不是完整拆装维修工艺。

## 排查入口

| 现象 | 官方提供的检查入口 |
| --- | --- |
| 更新后行为仍像旧版本 | `robotctl version`，对照正在运行与已安装版本 |
| 手柄已连接但不能控制 | `robotctl pad status`，分别确认连接状态和 `padd` 服务 |
| 手柄重启后不自动连接 | 如报告 `paired but NOT trusted`，重新执行配对以修复信任 |
| 指令与实际动作不同 | `robotctl monitor`，检查安全限幅、输入超时、测量角与目标角 |
| 舵机无响应或过载 | `robotctl health`、`robotctl monitor` 和 `robotd` 日志 |
| 日志持续出现 `bus read failed` | 除供电和连接外，核对快速同步读取的固件兼容条件，见 [操作与检查](操作与检查.md) |
| 头部 IMU 没有数据 | 先检查 `[head_imu] enabled`；它默认关闭采集，与 ID `200` 的身体 IMU 不是同一设备 |
| 更新失败 | `robotctl update log` 和 `robotctl update show` |

查看机器人控制服务本次启动的日志：

```bash
journalctl -u robotd -b --no-pager
```

需要重新启动舵机时，官方命令为：

```bash
sudo robotctl robot reboot-motors
```

此操作会关闭舵机扭矩，关节失去主动支撑，需先扶住机器人；之后需重新初始化。官方也支持在命令后指定要重启的真实总线 ID；ID 对照见 [关节名称与ID](../01-设备信息/关节名称与ID.md)。

## 单个舵机替换的软件识别

官方说明支持识别出厂默认配置的替换舵机：ID 为 `1`，波特率 `57 600`。

1. 按对应硬件的机械要求更换一个舵机。本次公开资料没有提供完整拆装步骤、螺钉扭矩与线束布置，不能由本页推定。
2. 舵机供电后，`robotd` 或其初始化流程会查找唯一未应答的关节。
3. 识别到新舵机后，软件将其设置为缺失关节的地址，写入寄存器并重启。
4. 在日志中核对 `replacement servo adopted`，再检查关节状态。

**一次只能处理一个缺失关节。**两个关节同时缺失时，软件无法判断新舵机属于哪个位置，会等待而不是自动猜测。适用舵机、电气条件和机械方向需与官方硬件一致，不能推广为任意舵机的通用替换方法。

自动分配 ID 只说明软件识别完成，不代表安装方向、零位、限位和实机验收已完成。可先按 [软件与传感器检查](操作与检查.md#6-软件与传感器逐项检查)核对数据和服务；当前未取得完整的厂家标定及维修后验收规程。
