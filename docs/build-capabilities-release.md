日期：2026-11-08。对应实现为 Build `source-model/1.15`、`assembly.catalog/3` 和独立 `assembly.requirements/2`；DKP 封套仍为 `psop.dkp/2.0-draft.1`。

当时复查版本为 `2.0.0-capabilities.4`，逐实例原装配用法、承座/端挡补录及 7 项未决问题见[完整性复查](reference-use-completeness.md)。此前 `.3` 增加[上游小位置偏差的合理修正](reference-assembly-repair.md)。本文保留首次 `capabilities.1` 的完整发布基线，后续包不改写其字节与测量记录。当前工作台版本及后续装配验证见 [Simulate 验收记录](simulate/verification.md)。

## 独立验收依据

设备要求位于 [capability-review.json](../device-materials/assembly/capability-review.json)，包含每份网格的源 SHA、局部范围、原三角见证与逐区要求，映射全部 70 个来源实例。首批 16 组问题作为回归种子，未把它们当作所有应有结构的清单。发现器不读取该要求文件。

顶点复核原件 [vertex-math](../device-materials/assembly/capability-review-vertex-math.json) 和 [facets](../device-materials/assembly/capability-review-facets.json) 随包单独捕获并锁定原字节。具体漏项、回归与三处混合壁修正见 [几何验收记录](build-capability-acceptance.md)。

左右外壳的竖向 Ø2.2 mm 孔及 Ø5 mm 阶梯段已作为独立有限段表达；大腿内锥孔、支承件锥销、镜头座主孔和径向孔，以及非圆键、凸耳和拔模导向均保留源材料见证。无法严格参数化的材料保留 `source_region`，不会用完整解析圆柱填补缺失材料。

本包没有将含未知残余的部件对归为 `no_match_in_scope`。面落座普遍存在，只代表保守的有限面必要条件，后续还需检查具体接触范围及构型。

孔组保存 23,848 个平行轴符号族和 8,412 个非平行轴符号族，允许部分成员、对称和入口翻转条件。完整关系已保存；成员映射并未提前全部枚举，`member_mapping_enumeration_complete=false`。查询预算耗尽时通过绑定输入的游标续查，不截成 Top K。

以下内容保持明确边界：

- 混合曲壁、自由曲面与未可靠分类区域保留有限原材料，不宣称全部具有解析参数或已确认用途。映射到来源实例后保留 3,309 个未参数化区域；单件解析材料比例最低约 2.76%，不能将三角覆盖完整说成全部形状或功能识别完毕。
- 有限孔壁边界／入口记录不自动证明孔口敞开、整条通道畅通或可从该侧装入；连续性只引用真实材料邻接见证。
- 光孔不升级为螺纹。缺具体型号时仅输出连接件参数要求；不编造 SKU、螺钉长度、BOM 或实际数量。本包实际标准件要求为螺钉、贯穿螺栓与可选螺母/垫圈；第三方标准销桥接两个孔尚无专门候选，允许类型库不代表所有标准件方案都已展开。
- 普通面候选只表示潜在落座或承托，不等于固定。未知运动归属、相位和制造公差继续保留条件。
- 每条候选固定 `assessment_scope=pose_independent_geometry`、`placement_evaluated=false`，没有已求姿态或组装成功状态。
- 本次 Build 发布时，Simulate 尚未消费新包执行共同姿态或多件装配。2026-11-10 后续已接入[工作台装配及终态检查](simulate/verification.md)；连续装入路径、保持、载荷及变体搜索仍未作为本次 Build 的交付结论。

## 发布验收结果

完整包已通过实际工作台 `loadPackage` 所调用的 Python 校验器，校验用时 117.630 秒；随后通过真实 `register` 登记到 Microduck 工作区并选中新快照 `dkp-aed80087d09929af30eb`，旧快照继续可读。

该次校验同时检查 manifest 全部文件清单和压缩字节 SHA、原始来源、独立要求、有限原三角、物理资源/入口、参考配置、每个实例对的完整候选关系及覆盖处置。更正统计、重新压缩或重新计算包摘要不能绕过独立缺项要求与候选见证校验。

最终验证器修正了两处发布链适配问题：来源摘要允许省略已按需读取的正文，但保持其路径、哈希和所有来源字段精确一致；验证返回使用工作台既有的 `schema` / `package_version` 等字段。两项均有回归测试，未改动已发布包的任何字节。manifest 的 toolchain SHA 仍记录实际产出包的生产器版本，后续重新准备需使用新工作目录和版本。
