# 设备工作区与工作台读取边界

> 2026-11-06（Asia/Shanghai）。本页补充 [系统设计](system-design.md) 中的设备工作区定义，接口限于本轮实际读取与登记范围。

## 1. 业务对象

统一工作台管理多个设备工作区。一个工作区围绕一个设备项目，保存稳定工作区 ID、设备 ID、可读名称和描述，并登记多个 DKP 快照。

DKP 快照通过 package ID、版本和摘要确定身份；工作区内的当前选择不是包的属性。设备名相同不能代替身份，包目录移动也不能自动成为新知识版本。

同一个工作区可以关联多个 Build 作业、模拟场景／会话、渲染批次、数据集、训练运行、模型和评测。后三类执行能力尚未接入时，工作台保持真实空状态，不预置成功记录或模型指标。

## 2. 登记

本轮通过本地工作台命令登记已发布的新包：

~~~powershell
node apps/workbench/scripts/workspaces.mjs register --dkp <新v2-DKP目录> --workspace <设备工作区ID>
~~~

登记前校验 DKP，保存其实际定位与不可变身份，不复制旧 App。已有工作区登记新快照时核对设备范围；不同设备不得因名称相似被混在同一工作区。

默认 Microduck 初始化入口是 apps/workbench 中的 npm run prepare:workspace。它调用新 Build 生成数据包后登记，不由工作台重新解析 ZIP 创建另一套知识。

## 3. 读取接口

| 请求 | 本轮作用 |
| --- | --- |
| GET /api/workspaces | 列出实际登记的设备工作区、可用知识快照和默认选择 |
| GET /api/workspaces/:workspaceId/snapshots/:snapshotId/view | 校验所选快照，返回供通用界面使用的显示投影 |

工作区对象包含 id、deviceId、name、description、snapshots；快照包含 id、packageId、packageVersion、packageDigest、ontologyVersion、createdAt 和 counts。选择快照须使用实际列表中的 ID。

目录请求核验已登记 manifest 的摘要与设备身份，返回元数据，不重放所有历史包的几何，也不声称内容已经通过本次验证。选择知识／读取资产时核验完整包及来源重放，读取文件时继续检查登记字节身份。历史包几何复杂度不应阻塞目录。

显示投影关联新包身份与能力。资产 URL 由工作台服务挂载并返回，客户端不拼接任意本机路径。原件、XML／CSV 定位和几何绑定仍指向该包版本，搜索、3D 和证据页面共享同一上下文。

feature、hole、pattern、observation 与 interface 的选择和链接分别保留类别。1.4 增加安装孔位、参考安装和槽开口的定位，1.5 另支持实体安装柱、局部功能声明与未知选择规则；1.6 按连接链加入内腔、逐对审查和补全示意，小柱用途更正为项目推断；1.7 增加柱孔有限配合及补全件用途分级，当前 1.8 修正参考连接件的方向并记录有限装入假设。同一孔组的两侧布局作一个布局的入口详情，不以 02／03 同名条目冒充两个功能对象。安装页展示有依据的孔位、规则及双方对应，缺项按能力分别说明。旧 1.0～1.7 读取冻结合同；1.1／1.2 只作历史几何浏览，均不以零数量声称不存在装法。

接口页以本件实际配合和作用为主线：双方局部位置 → 定位／保持分工与依据 → 已有规则、参考对应及缺项。孔位、小柱的定位保留当前接口上下文，显式查看原始几何才切换分类。逐对连接分析、辅助几何及缺项折叠呈现，并有独立审查页；邻接筛查不取代接口清单。大腿每两根小柱与同台舵机壳体 B2／B3 孔对应，16 mm 组距、约 2 mm 有限插入和模型间隙支持安装定位用途推断；不形成“至少双柱”规则、轴向保持或承载结论。外侧 Ø5.5 mm 大洞另列为用途未知的几何，不作为默认主接口或装饰。

有来源参考安装路径的连接件示意（reference_connector）与未核实替代示例（unverified_alternative）分开组织。厂商轴心螺钉／压盖属于后者，默认不显示，显式查看也不进入当前保持链。每类可独立显隐及定位；合成件保留独立身份与未确认状态，实际螺钉长度待确认，图形尺寸不成为实物规格或确定 BOM。1.6 历史大洞关联和示意件不能在消费时升级为当前固定依据或 Simulate 已固定标签。

读取层及索引可以缓存或重建，但不得修改已发布包或改变事实。旧 DKP、错误摘要、未知封套和缺失文件明确失败，不偷偷降级为旧 App 或示例数据。

### 接口面板的通用消费规范

当前面板按以下规则整理：参考安装在原卡内列出具体对应及紧固要求，不再追加重复详情；孔位池、测量和原件清单按需展开。1.8 修正标准双孔连接件的示意方向并进行有限几何一致性检查，实物装入侧和完整机械路径仍未确认。机器数据层次遵循[规则、绑定、操作和显示的一致性](assembly-interfaces.md#9-规则绑定操作和显示的一致性)。

每个接口／部分安装定义先回答本件有哪些有依据的能力，再列该能力下的参考安装或当前候选绑定。一个具体绑定包含所用模式、参与者、选定成员、对端映射、中间件及共同配置，不以一个 Part 对或一个孔号作为全部身份。多层连接、不同机制和未核实方案沿相同语义组织，不复制成若干看似已确认的接口。

默认只呈现该上下文的简短结论和关键未决项，选择后在原位置展开同一绑定的原子对应、保持／操作条件及证据；不在页面末尾再次追加同名参考装配。同一关系可以有多个导航入口，但只保留一份主详情。定位改变选中及视图，不自动完成选孔、创建实际连接或使检查通过。

| 内容 | 呈现与交互要求 |
| --- | --- |
| 可用成员与选择规则 | 显示能力范围；同侧可选组合用 `{A1,A2}` 等集合表达，并注明最少数量／完整性依据；不假装本次已用 |
| 具体参考／候选绑定 | 单独列双方或多方的实际角色映射，如 `舵机 B2 ↔ 连杆 L1`；身份、适用配置和未决条件可追溯 |
| 操作与保持 | 已知对应、装入方向、保持方式及执行状态分项显示；“未知方向”“未绑定连接件”不能被一幅确定姿态的图形遮盖 |
| 中间件与示意 | 分清已识别实物、未绑定角色和纯方案示意；未绑定时写“2 条紧固路径，连接件未绑定”，不写“本连接有 2 颗固定件” |
| 当前选中详情 | 只展开当前成员、绑定、路径或假设的详情；参考配置不标成当前实际已安装，多个方案不默认同时成立 |
| 证据与来源 | 当前结论附近给简短依据及定位入口，原件清单／完整参数默认折叠；同一审查的全部文件不冒充每一结论的直接证据 |

几何入口、逻辑孔道、接口定义、参考关系、紧固要求路径、已绑定物料和纯示意件分别统计，不相加成含义不明的“接口数”或“固定件数”。例如八个入口仍可只关联四条孔道；两条紧固要求不等于已识别两颗实物螺钉。

接口页回答“能怎样连接、本次或参考使用了哪些位置、作用与缺项是什么”；关联页回答“与哪些对象、活动框架或模型关系有关”；证据页集中检查具体断言和原件。三页共享对象／绑定／版本上下文，不各自重建连接事实。高亮、透明、爆炸和假设示意始终属于显示状态，不作为任何机械结论的来源。

## 4. 状态隔离

当前工作区、快照、模式与视图是工作台上下文。切换设备或版本时取消旧读取，重新核对选中对象、证据和场景；异步旧响应不能覆盖新选择。

对象详情栏宽度是本机布局偏好，可拖拽或用键盘调节并持久化；最小 320px、默认 380px、最大 640px，双击分隔条恢复默认。实际最大宽度受可用空间约束，为 3D 画布保留显示范围，窄屏通过收起结构树或改变面板布局处理。

定位被遮挡的特征时采用临时局部查看和透明，可恢复原场景。局部检查状态及当前连接固定件的显示范围随视图分享／导出保存，属于可变显示状态，不写回冻结 DKP。这些操作不改变来源几何、参考位姿或机械判断，也不新增后端、模拟或物理执行能力。

模拟会话、人工候选、训练和推理消息是包外可变状态，未来通过相应执行服务写入。当前读取 API 不构成模拟动作、训练或发布 API。新增运行接口应有输入锁、任务身份、状态与失败语义，不能仅添加前端按钮。
