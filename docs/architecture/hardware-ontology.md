## 1. 目标与范围

PSOP 从一个开源项目的资料中，还原可追溯的部件、几何、接口、装配关系和内部运动，使模拟环境能够支持接口尝试、逐步组装、误装识别、拆改纠正，以及已装部分在当前约束下的运动。

本体为这些能力提供共同语义：**部件有什么、接口能发生什么作用、当前实际形成了什么关系、这些关系允许怎样运动、距离任务要求还差什么。**

| 目标能力 | 本体必须提供的知识 | 对应判断 |
| --- | --- | --- |
| 还原项目 | 来源版本、部件身份、规格、几何、参考装配及内部运动 | 还原了哪些内容，依据和缺项是什么 |
| 尝试不同接口 | 特征、作用机制、双方角色和空间条件 | 哪些组合已知可行、不可行或待确认 |
| 保留用户误装 | 当前选择的真实端点、局部作用关系和状态 | 接得上但接错对象、方向或接口时，错误在哪里 |
| 验证装配 | 机械条件、工程要求、任务约束、完成条件及证据 | 当前关系是否成立，是否适用，是否满足目标 |
| 逐步引导 | 可复用操作、转换条件、局部效果、诊断引用 | 当前能做什么，哪些操作有助于纠正或完成 |
| 调整已装部分 | 活动框架、内部运动、阶段约束、限位与碰撞条件 | 哪些相对运动仍可发生，哪些变化会被阻止 |

“完整还原”必须针对明确的项目版本、对象范围和用途判断。只有网格时，可以完成相应外形的重建；缺少接口尺寸、材料、连接件或装配依据时，不宣称已经完成工程还原。合成案例通过，只证明相应表达和实现案例通过。

当前范围包括机械部件、采购与制造描述、空间语义、机械连接、内部运动、装配任务和操作语义。电路、通信协议、软件部署、完整控制系统、材料破坏及完整动力学不作为本版的必备实现；任务依赖这些能力时须明确扩展要求或未支持项。

具体 Plan、Execution、交互事件、求解算法与提示排序由运行时承担。本体定义其需要引用的对象、条件和变化语义。

### 1.1 本次修订的决定

本版集中确定六项规则：框架的运动依附与坐标表达分开；连接变更保留局部连续性映射；历史证据与当前支持关系分开；判定结果具有统一合法组合与聚合规则；候选求解态通过明确检查后才能成为权威模拟状态；完整机器示例区分输入、约束、求解结果和验收依据。

这些规则是 PSOP 的规范选择。外部项目提供对照和边界依据，不自动证明 PSOP 已具备相应能力。

## 2. 四类判断与错误装配的地位

### 2.1 四类判断分别表达

| 判断维度 | 定义 | 典型问题 |
| --- | --- | --- |
| 机械可实现性 `mechanical` | 在声明的几何、运动和接触模型下，某一接合、保持、位姿或运动条件是否成立 | 是否干涉；是否能进入；是否已经形成保持；能否继续转动 |
| 工程适用性 `engineering` | 该组合在指定工况下是否符合适用的规格、材料、载荷、工艺和使用要求 | 连接件等级、有效啮合、材料和防松要求是否满足 |
| 任务符合性 `task` | 当前部件选择、关系、方向和运动能力是否符合当前 Task | 是否接到指定对象；是否保留要求的输出运动 |
| 完成与验收 `completion` | 某条路径、某项转换或整个任务的完成条件及证据要求是否满足 | 是否插到位；哪些紧固路径已完成；完成证据是否充分 |

这些维度可以引用同一个条件，但不能互相代替。一只错误支架可以已经接合并完成紧固，同时不符合任务要求；一颗不适用的螺栓也可能在几何上装得进去。局部连接完成，不等于整个任务通过。

机械判断必须说明检查范围。终态位姿可成立、操作路径可到达、规定载荷下可保持，是不同结论。

### 2.2 合法数据可以描述错误状态

数据结构有效性与上述业务判断分开。格式错误、悬空引用、单位维度错误属于无效输入；部件接错、方向错误、操作未完成属于应当能够表达的状态。

| 情况 | 记录和处理原则 |
| --- | --- |
| 机械关系成立，任务不符合 | 可以成为当前模拟配置；实际成立的约束继续生效 |
| 机械关系成立，工程要求不符合 | 保留状态和工程问题；不授予相应适用或验收结论 |
| 尝试受到已确认的机械阻挡 | 保留实际已达到的位姿、接触或部分插入；不写入未发生的成功效果 |
| 缺少事实或计算能力 | 保留未决条件；需要假设演示时进入明确标记的假设分支 |
| 导入配置与当前模型不一致 | 保留来源配置及残差，报告不一致；不自动认定现实不可能，也不静默修正来源 |
| 普通中间态尚未达到目标 | 表达待装、未完成或待检查；仅凭最终目标未满足，不认定误装 |

试错模式允许用户实施机械上可发生但不推荐的动作。引导模式可以限制交互范围，但限制属于交互策略；不得据此改写接口能力。破坏性强装、材料损伤等需要对应模型，本版基础能力不以刚体穿透模拟这些行为。

### 2.3 本版的基本不变量

1. 当前实际连接决定当前机械行为；任务目标不直接生成物理约束。
2. 误装连接只要机械作用已经成立，就参与占用、连通、联动和运动计算。
3. 参考模型中的终态和装配树不自动成为当前模拟的固定结构。
4. 未知不是否定，计算失败也不自动证明机械上无解。
5. 失败尝试可能已经产生部分变化；只提交实际达成或明确假设的效果。
6. 局部完成、整体完成、当前连通和刚性固定分别判定。
7. 一个任务可以有多个满足条件的配置；替代方案按任务要求判断。
8. 模型或假设中的成功，不自动成为实物已经完成的证据。

## 3. 对象、身份与关系

### 3.1 核心对象及支持结构

| 对象或结构 | 定义 | 身份与职责 |
| --- | --- | --- |
| `Part` | 参与装配的具体部件对象 | 移动、拆下或成为备件不改变身份；可包含内部运动 |
| `Interface` | 某 Part 对外发生装配或机械相互作用的能力描述 | 关联特征、框架、作用机制、条件和依据 |
| `InterfaceConnection` | 某配置中选定端点之间的一项具体关联 | 绑定实际参与者、机制、局部关系及状态；可以未完成或不符合任务 |
| `Configuration` | 冻结版本的部件、关系、构型和依据快照 | 同时容纳分离部件、部分装配和多个组合 |
| 可复用规格 | 型号或设计修订、属性、几何及接口模板 | 不作为装配参与者；可描述单件或总成 |
| `Feature / Frame / RigidSegment / MotionDefinition` | Part 内具有稳定键的空间与运动结构 | 表达有限作用几何、参照系、刚性区域和内部运动；没有新增装配使用身份 |
| 连接方式及机制字典 | 角色、特征选择、作用机制和条件模板 | 可引用、可参数化，不增加装配使用身份 |
| `Task` | 可接受配置的目标条件、持续约束和验收要求 | 可以引用参考配置，但不以参考步骤作为唯一允许路径 |
| `Operation` | 可复用的机械变化和检查语义 | 指定参与角色、机械条件、局部效果与验收引用 |
| 属性主张、来源、条件和证据 | 附着于相应对象的知识结构 | 保留来源、适用范围、版本及不确定性 |

Part、Interface、InterfaceConnection 保持为装配主干。没有额外的 PartUsage 或 FunctionalPosition 身份层；条件及证据按所属对象组织，不建立独立 reasoning 或 assurance 领域模块。

### 3.2 身份、域与版本

同规格的 S1、S2 是不同 Part。接口引用至少能解析到部件身份、部件描述修订和接口键；特征引用遵循同样规则。名称、采购 SKU、文件名、网格三角面编号不替代语义身份。

Part 的对象域为 `model`、`physical` 或 `synthetic`。没有实物识别依据时不创建已确认的实物主张。模型部件与实物部件需要有依据的对应引用，保存适用配置、版本、对应范围和识别证据；共享规格不能自动建立对应。

配置固定所引用的规格、部件描述、接口定义和几何版本。升级定义后创建新配置或显式迁移；历史快照不沿 `latest` 自动更新。

连接 ID 标识一组具体的端点、角色、方式和特征绑定。在这些绑定不变时，状态和构型变化可以沿用连接 ID；更换参与部件、方式或所选特征时创建新连接 ID，可附 `replaces_ref` 说明关联。局部记录以 `(configuration_id, connection_id, local_key)` 唯一定位，证据必须引用其适用快照。

### 3.3 局部连续性与证据复用

整条连接更换 ID，不要求所有未受影响的局部作用失去连续性。新配置可以提供 `continuity_map`，逐项说明旧、新局部引用的关系。`replaces_ref` 仅表示替换关联，不代替这张映射。

| 映射内容 | 规范要求 |
| --- | --- |
| `from_ref / to_ref` | 精确指向两份快照中的局部作用、路径或端点，不只引用父连接 |
| `relation` | 区分 `continuous`、`same_binding_reestablished`、`modified`；相同端点不自动证明连续 |
| 绑定一致性 | 连续项的部件、特征、角色、机制及相关定义版本必须对应 |
| 过程依据 | 说明检查范围内未解除该作用，或其保持条件沿已接受变化持续成立 |
| 影响范围 | 记录可能变化的几何、载荷、边界、邻接关系、模型和假设依赖 |
| 判定迁移 | 逐条件标明可以重用支持、需要重算、已失效或仍未知，并给出依据 |

例如只更换 p2 的螺母时，可以映射旧 C0.p1 到新 C1.p1。若 p1 的绑定与过程保持不变，其作用可以连续；其几何识别依据可能可重用，而与整体载荷或预紧状态相关的结论仍需重新判断。拆开后再接回相同端点，应标成重新建立，不能继承上一次紧固事实。

对同一个不可分的局部作用，`continuous` 映射必须一对一。拆分、合并或复制造成的多对多关系只能声明相应派生，不将一份历史证据复制成多份独立支持。定义版本须一致，或具有针对该依赖的等价迁移依据；名称相同、网格索引相同不构成依据。

历史证据保持原始对象、配置、时间和内容。新配置产生新的支持关系或判断，引用旧证据并说明适用理由；不得把旧证据的配置引用直接改成新配置，也不得把派生缓存继续存在解释成证据仍然有效。[S13]

### 3.4 复合部件与层级

总成规格可以复用；不同总成实例及其内部部件分别具有身份。实际成员关系和暴露接口映射由 Configuration 的 `composition` 作为权威记录，规格保存结构模板，复合 Part 引用相应配置。

同一配置内，物理包含关系无环，一个内部部件最多有一个物理父级。功能分组、来源文件树和物理包含分别表达。对外暴露接口必须解析到内部接口及原特征，不复制孔、轴或连接能力。

集合成员、物理连通和刚体分组分别判断。BOM 只表明组成要求；实际连通由已经成立的机械作用决定；刚性联动还需满足相应运动约束。

复合 Part 展开为内部成员时，应指定代理几何与成员几何的用途和当前有效表示，避免父级代理与子部件同时作为重复的独立碰撞或惯性实体。切换细节层级不得增加或删除实际连接事实。

## 4. 开源资料、规格与还原范围

### 4.1 来源与映射

来源记录至少包含项目或资料地址、版本或提交、文件路径及摘要、资料类型、许可信息、取得时间、定位方式和支持范围。可定位到图纸区域、文档段落、BOM 行、CAD 对象或模型节点。

导入映射必须区分三种内容：

- 产品内部的组成或运动关系，例如舵机外壳与输出轴之间的运动。
- 项目的参考装配关系，例如哪只舵机装到哪个支架。
- 为模拟、显示或简化而增加的假设，例如世界固定、忽略某对碰撞、理想焊接。

CAD occurrence、MJCF body、URDF link 和网格对象只提供来源节点身份，不能自动等同于可拆装 Part。来源映射可以是多对一或一对多，须说明依据及尚未识别的范围。

参考装配导入为参考配置和连接知识。用户试装时，后端依据当前连接重新建立相应约束，不能沿用参考装配树把可接错的端点提前锁定。

### 4.2 属性、采购与制造

属性字典定义语义 ID、适用对象、值类型、维度、单位、条件值规则与允许证据。属性主张区分 `design / nominal / measured / calculated / assumed`，保存值、条件、版本、来源及不确定性。标称值与测量值可以并存；冲突不通过任意覆盖解决。

规范单位采用 m、rad、kg、N、N·m、s 等；四元数、计数和比例有独立类型。外部 mm、degree 等在明确的位置转换一次。测量不确定性、制造公差、几何拟合误差和数值求解容差分别保存。

采购项关联准确商品变体、卖家或 SKU、链接、核查时间及必要地区和包装条件。系列名不能自动补成精确型号；采购入口不要求必须来自原厂，来源可信度与规格对应程度分别说明。

制造描述绑定设计修订和文件摘要，按用途保存材料、工艺、关键尺寸及公差、制造方向、必要工艺参数、后处理、检验要求与使用限制。可引用受控打印或加工工程。STL、参数齐全和一次试装成功都不自动证明制造或工程适用性。

### 4.3 按用途报告覆盖范围

| 用途 | 需要确认的知识 |
| --- | --- |
| 几何浏览 | 来源、身份映射、单位、可显示几何和坐标关系 |
| 参考几何观测 | 特征与测量框架、固定配置中的有限测量、数值阈值及覆盖；不声明功能作用 |
| 接口假设 | 有限特征、本方及互补角色、具体机制、功能来源或可复验功能结构见证、组合条件及未决项 |
| 机械交互 | 当前机制、有限几何、阶段约束、接触或简化模型 |
| 运动验证 | 内部运动、外部连接约束、限位、相关碰撞与计算能力 |
| 工程适用 | 对当前工况真正必要的规格、工艺、载荷与证据 |
| 实物验收 | 对应实物、适用完成条件、现场证据及其范围 |

覆盖范围可以按对象、接口、性质或资料域分别声明。缺失不为所有字段制造空值；只有明确枚举完整的集合，其缺席才支持否定结论。

## 5. 空间语义

### 5.1 空间语义必须有可计算的载体

空间描述由三部分对应：**语义对象标明在谈论什么，数值与几何定义其空间含义，图示帮助人理解。**“左侧”“孔口”“朝外”“对齐”“插到底”等标签必须能解析到框架、几何或条件。

| 空间层次 | 结构化载体 | 示例 |
| --- | --- | --- |
| 参照与依附 | 有稳定键的 Frame、数值参照和运动载体 | 外壳框架、输出轴框架、安装入口框架 |
| 几何 | 有界解析几何、CAD 拓扑引用或版本化网格区域 | 孔道、轴段、承压环面、键槽 |
| 定位 | 框架间变换及其性质 | 设计相对位姿、求解位姿、观测位姿 |
| 关系 | 明确两端、方向、区域与容差的谓词 | 同轴、法向相对、包含、重叠、沿轴深度 |
| 路径 | 带参照框架、参数和检查范围的位姿轨迹 | 接近、插入、旋入、退出 |
| 运动 | 坐标、变换映射及当前激活约束 | 输出轴转动、插入导向、锁止后的保持 |

空间标签不单独决定正确性。例如左右必须指明参考框架和轴；相对于观察者的屏幕左右不能作为机械判断依据。

### 5.2 坐标系与变换约定

每个 Part 有一个根框架并指定其对应的基准刚性区域；Feature、Interface 和运动结构引用所属框架。一个 Part 可以声明多个局部刚性区域 `rigid_segments`，例如舵机外壳与转子；这些区域服务于几何和运动归属，不成为独立装配部件，也不代表已经还原未知内部零件。

Frame 必须区分以下关系：

| 字段或关系 | 含义 |
| --- | --- |
| `owner_ref` | 该语义框架由哪个 Part 或环境定义 |
| `attached_to` | 框架刚性依附的局部区域或环境载体，决定随谁运动 |
| `pose.expressed_in` | 当前位姿数值在哪个框架表达，不决定运动依附 |
| `motion_ref` | 决定所属区域运动的定义引用；不是给同一 Frame 再增加独立驱动 |
| `definition_revision / evidence_refs` | 当前定义版本与来源 |

Part 所属 Frame 的 `attached_to` 只能解析到该 Part 内的刚性区域；环境 Frame 可依附其环境载体。跨 Part 的机械依附须经当前具体 coupling 表达，不能利用 Frame 的依附关系绕过实际连接。`expressed_in` 可以跨对象选择参照。

坐标解析图须能唯一求值；无解的循环引用是输入问题。机械连接构成的闭环则交由共同约束求解，不通过篡改坐标树消除。选择世界框架表达自由部件的位姿，不等于把该部件固定在世界。该区分参考 SDFormat 的 attached_to 与 relative_to 语义。[S1]

本版使用右手坐标系和列向量。`T_A_B` 将 B 框架坐标转换到 A 框架；平移量在 A 中表达。旋转矩阵满足 `v_A = R_A_B · v_B`；四元数使用 `xyzw`，表达与该矩阵一致的旋转，比较旋转时 q 与 -q 表示同一姿态。

采用单位 Hamilton 四元数，组合满足 `q_A_C = q_A_B ⊗ q_B_C`，对应 `R_A_C = R_A_B · R_B_C`。绕 +Z 的正 π/2 旋转将 +X 映到 +Y。归一化阈值由数据剖面明确；非有限值、零范数不得参与计算，允许的数值归一化保留原值及修正量。

`p_A = T_A_B · p_B`

`T_world_feature = T_world_part · T_part_frame(q) · T_frame_feature`

Frame 相对其 `attached_to` 刚性区域的局部位姿为常量；MotionDefinition 驱动区域之间的相对位姿。附着于活动区域的 Frame 随该区域一起运动，相对于其他表达框架的数值可以变化。若存储 `motion_ref`，它只能引用这条生成关系，不能重复施加运动。缩放在源几何归一化时处理，不作为 SE(3) 中的自由变换。导入需显式处理源坐标轴、手性、单位和四元数顺序。

位姿记录必须指明表达框架、被定位框架、平移和旋转，以及 `design / observed / solved / assumed` 性质。观测值保留不确定性和来源；对观测的拟合或投影另存结果与残差。

每个空间变量有明确的权威生成方式：独立配置输入、运动定义求值、共同求解或观测主张。可缓存其他表达，但必须保存依赖版本；导出格式中的同名字段不因此获得第二份独立权威。

### 5.3 特征必须指向有限几何

Feature 包含类型、所属框架、几何定位、有限作用区域、有向语义和版本依据。解析几何可以直接描述圆柱、平面及区域；CAD 引用须可定位到对应设计修订；网格识别特征须保留拟合方法、区域和误差。

| 特征 | 至少需要区分的内容 |
| --- | --- |
| 孔或通道 | 轴、入口、出口或盲孔终点、截面、有效长度、内壁区域 |
| 轴或插入件 | 轴线、前端、轴段范围、截面、台阶及止挡面 |
| 面 | 平面或曲面、边界区域、有向法向、是否为接触或承压区域 |
| 螺纹 | 作用区域、轴、旋向及适用规格；几何近似与螺纹语义对应 |
| 槽或键 | 有界空间、入口、键位方向和接合区域 |

包围盒用于粗筛时必须标明用途，不能直接承担螺纹、孔道或接触面的验收判断。渲染网格、碰撞几何与测量几何可以不同，但须分别注明修订、精度和适用检查。

导出后端时必须保存几何用途和近似信息。例如 UsdPhysics 将该类 plane collider 按无限半空间处理，忽略可视平面的有限绘制范围；因此一个有限承压面不能在无说明的情况下直接转成这种 collider，再用于证明有限区域接触成立。[S3]

近似结果须说明可支持何种结论及其保证方向。粗筛候选、有限区域接触、精确终态和连续路径检查分别保留结果；一种近似的通过不自动代替另一种检查。

### 5.4 空间关系的最小结构

每条空间条件至少明确：`condition_key`、关系类型、作用对象、表达或比较框架、所用几何区域、有向性、目标值或区间、容差及来源、适用条件、所需计算能力。

| 关系 | 必须明确的语义 |
| --- | --- |
| 同轴 | 比较两条轴线的方向与偏移；是否只检查基准残差，或检查有限配合长度 |
| 平行与垂直 | 比较方向或法向；垂直是否还要求相交 |
| 共面 | 法向及法向偏移条件；不自行推出有限面重叠 |
| 面朝面 | 有向法向满足相对要求，并分别检查区域、距离和接触条件 |
| 左右、前后、上下 | 在指定参照框架中，对指定点、区域或整体边界施加投影条件 |
| 包含与贯穿 | 有限几何之间的范围关系，明确入口、出口、作用段与边界 |
| 插入深度 | 指定前端或基准点相对入口，沿指定有向轴的有符号位移 |
| 间隙与干涉 | 所声明几何及误差模型下的距离或相交条件，保留接触例外 |
| 相对位姿 | 比较 `T_A_B` 与目标位姿或位姿集合，不只比较中心距离 |
| 接触 | 指定有限接触区域和接触模型；接触不自动构成保持或固定 |

同一条件的语义不因接口名称、观察相机或渲染颜色变化而改变。坐标表达变换后，几何条件的判断应保持一致。

涉及两个部件的配合须保留双方局部锚点，而非只保存一个世界空间目标位姿。后端可将其映射到类似 OpenUSD Joint 的两侧局部位置与旋转字段；是否启用关节、是否过滤碰撞仍只是后端配置，不构成接合或完成证据。[S2][S3]

### 5.5 几何残差与容差

对同一框架中的单位向量 u、v 和固定定义的基准点 p、r，可采用以下教学残差：

- 无向夹角：`acos(clamp(abs(dot(u,v)), 0, 1))`。
- 有向向量夹角：`acos(clamp(dot(u,v), -1, 1))`。
- r 到第一条基准轴的距离：`norm(cross(r-p, u))`。
- r 到第一基准平面的距离：`abs(dot(r-p, u))`。

这里的点到轴残差不表示任意异面轴的最短距离。基准点、检验长度和区域须固定；非零角度偏差下，基准位置合格不能替代整段配合的偏差判断。上述约定也不替代 GD&T 标准中的完整检验方法。

“同轴”默认是无向轴线关系；插入方向、键位及面朝面另用有向条件。容差分别标明来源与用途，不把求解容差写成制造许可。

### 5.6 路径、扫掠体与可达性

路径可以参数化为 `T_reference_moving(s)`，并声明起点、终点、方向或允许路径族、相关关节坐标、运动对象、保持约束及检查范围。离散采样时须注明采样策略与检查保证；不能把若干采样点通过称为连续路径已经证明畅通。

参照框架本身运动时，世界路径按 `T_world_moving(s) = T_world_reference(s) · T_reference_moving(s)` 计算。相对位姿恒定仍可能产生世界空间中的运动和扫掠。相关活动框架及随动部件使用同一条已求解的构型路径。

进入和退出条件分别定义。静态终态存在不证明从当前配置可达；退出也不默认等于插入路径的无条件反向。工具、连接件和被带动部件按需要进入扫掠与碰撞范围。

柔性变形、压配或卡扣若没有适用模型，返回对应计算不支持或知识不足。允许展示未验证路径时，必须保留其假设性质。

### 5.7 空间例子与待核验机器示例的对应

一个合成孔口框架以 +Z 表示向孔内的方向，孔轴穿过局部原点。插入件前端位于该框架的 z=0.005 m，前向轴为 +Z，则有符号进入深度为 0.005 m。将插入件绕自身 x 轴旋转 π 后，无向轴线可以仍然同轴，但其前向轴变为 −Z，有向进入条件改变。

本段按前端点定义深度。提交稿拟在机器示例中采用 `depth_m = dot(origin_bolt − origin_receiver, axis_receiver) + seated_depth_m` 作为操作坐标；检查器必须核对该值与实际几何一致。两种深度参数须按各自参考点与零位转换，名称相同不代表数值定义相同。

这个例子只支持所声明的轴线、方向和深度结论。是否能沿路径进入、是否形成保持以及是否符合任务，还需对应条件。机器示例必须补齐实际可解析的 Part、局部区域、Frame、Interface、连接路径、Configuration 和 Task，检查空间与状态链条；完整材料尚待提供，见第 14、15 节。

## 6. 部件内部运动

### 6.1 一个 Part 可以包含多个活动框架

舵机可以保持为一个 Part，同时拥有外壳框架和输出框架。外壳几何、安装孔关联外壳框架；输出轴、输出接口及对应几何关联输出框架。只要资料支持输出运动，就可以描述该运动，不必虚构内部齿轮结构。

`MotionDefinition` 是 Part 内的结构，至少包含：

| 字段组 | 含义 |
| --- | --- |
| 身份与作用框架 | 稳定运动键、父/子刚性区域及双方局部关节框架 |
| 运动类型 | 固定、转动、移动、球形、螺旋或明确定义的参数化变换 |
| 运动参数 | 零位关系、运动轴及其表达框架、变换映射 |
| 坐标定义 | 坐标键、单位、周期性及必要的坐标域 |
| 范围 | 来源模型范围、设计允许范围、实物限位分别描述 |
| 依据 | 版本、来源、误差、简化假设及适用条件 |

Configuration 保存坐标值或有依据的区间。活动框架位姿由运动定义导出；缓存须标明依赖版本，不能成为第二套独立可写的位姿事实。观测位姿作为独立证据与计算结果比较。

坐标解析唯一是指引用和生成规则不歧义，不要求未知或区间坐标一定产生单个位姿。区间输入须保留相应构型集合，说明检查采用存在性还是全称含义；不默认取中点后报告整个范围通过。本版机器示例仅使用确定的坐标值与明确的解析区间检查。

源格式的一个 rigid body、link、segment 或 prim 与 Part 之间由明确映射连接。外壳和转子可以映射为多个后端刚体，仍属于同一个舵机 Part；反向导入时也不按后端刚体数量自动创造采购件。

每个范围还须注明用途。已确认机械止挡或当前模拟明确采用的机械限位进入相应物理模型；设计推荐区间、软件设定区间和任务工作区间分别进入工程或任务判断。后端模型范围若仅为简化假设，保留该性质，不直接推出实物存在相同止挡。

### 6.2 运动定义与操作许可分开

存在一个运动自由度，不代表任何工况下都可以无条件操作。例如被其他连接阻挡、限位已到达、工具暂时占据通道时，当前可动范围会改变。推荐操作还可能依赖工艺或任务要求。

“期望输出轴转动”是任务要求；“输出轴在当前约束下可以转动”是机械判断；“已经转到规定角度”是当前状态；三者分别表达。

## 7. 接口、连接方式与候选

### 7.1 接口描述可发生的作用及其条件

Interface 关联所属 Part、接口键、框架、特征和一组连接方式。几何存在、机制推断、工程批准是不同知识地位。只有来源支持的范围才标为已确认；资料不足时保留未解析特征或候选机制。

| 方式结构 | 需要表达的内容 |
| --- | --- |
| 机制与本方角色 | 通孔夹紧、螺纹承接、导向、转动支承等机制，以及本方承担的角色 |
| 特征选择 | 可作用的特征及组合表达式，保留原始特征身份 |
| 对方要求 | 互补角色、几何和机制条件，不以已知成功产品名单替代 |
| 连接件要求 | 所需连接件角色、数量及各自接口 |
| 机械条件 | 接触、接合、路径、保持、占用及运动所需条件 |
| 工程要求 | 适用规格、载荷、工艺、寿命或其他使用条件 |
| 状态谓词 | 对齐、进入、啮合、保持、锁止、退出等条件，按具体机制定义 |
| 约束模式 | 哪些局部状态会激活哪些空间或运动约束 |
| 转换 | 机械前置、局部变化、不变量、可逆性及完成条件 |
| 依据 | 来源、推断或假设、适用版本、能力覆盖范围 |

方式必须分别保存机械条件与工程要求。项目特定的“必须接 S1”“必须使用设备左侧接口”等要求归属于 Task。接口不能通过一个混合的 `allowed` 字段把三者合并。

### 7.2 机制字典与双方互补

机制字典定义角色名称、共同作用关系及参数含义；接口方式引用机制，并提供本方特征、参数和适用依据。连接完成角色绑定后实例化共同约束。可以复用机制模板，但不以模板名称相同作为匹配证明。

例如外螺纹与内螺纹承担互补角色，通孔板与螺母承担不同角色。双方条件共同检查；冲突不能通过优先采用某一方的描述消除。同一条件可共享引用，避免不同接口复制出多份不一致的定义。

几何模型推断出的机制可作为待验证候选。需要通过假设才能使用的条件，必须保留假设与其影响的判断范围。

### 7.3 特征选择与候选结果

候选绑定包含角色、接口方式、特征映射、待满足条件及来源。选择表达式描述组合空间，候选不是已经发生的连接。

| 算子 | 语义 |
| --- | --- |
| `FEATURE / REF` | 引用已有特征或展开明确的方式结构，保持原始身份；引用无环 |
| `AND` | 合并相容角色绑定与共同条件；特征身份去重不等于使用次数或作用关系去重 |
| `OR` | 保留分支来源的候选并集；不自动同时采用所有方式 |
| `SELECT` | 从有限集合按数量、必选项和条件选取子集 |
| `MATCH` | 按角色定义建立特征映射；明确一对一、多对一或其他受控基数 |
| `REQUIRES / EXCLUDE` | 附加依赖或排斥条件，同时注明它属于机械、工程还是任务要求 |
| `SHARE` | 按明确规则检查共用关系，不覆盖已有互斥或几何阻挡 |

候选评估结果须保留各维度判断和枚举完整性。`unknown` 保留待决条件；计算未支持或搜索未完成不能返回一个被解释为“已穷尽且无候选”的空集合。

候选查询须注明用途：寻找机械接合、寻找满足工程要求的组合、寻找任务解，或评估用户指定的尝试。寻找任务解可以过滤已确认不符合目标的候选；评估用户试装时必须仍能解释这些候选的机械行为。

例如四孔任选两孔的六个子集可以进入几何候选。若资料只批准其中的对角组合，批准范围作为工程要求；若某一任务另指定一个孔组，作为任务条件。不能因为任务只选一组，就把其余孔从部件能力中删除。

### 7.4 并用与占用

共用判断以部件身份和特征身份为基础，并追溯到具体作用区域、轴向区间或通道。一根螺栓贯穿多层板与两根螺栓独立占据同一通道，属于不同机械关系。

占用由当前实际作用及机制条件决定，不能统一设置所有 Feature 的 `capacity=1`。表面可以有多个不重叠作用区，通道可在不同阶段具有不同可用空间；未知并用规则不能被推定为允许或禁止。

解锁、松开与完全退出分别判断。解除保持后，导向、接触和通道占用可能仍然存在。复合件暴露接口须先解析到内部特征，再检查已有关系。

### 7.5 原子孔与参数化安装方式

一个逻辑孔可由多个壁段、端口和肩面共同描述，不增加 Part 身份。阶梯孔的多段壁不增加孔数；同轴近邻不能替代孔道连续性检查；同一通道的两端口也不等于两个独立孔。

安装孔位是有功能依据的可寻址入口角色，引用孔道、有限 Feature、具体端口和进入方向。四条双入口孔道可提供八个安装孔位；它们在装配层分别寻址，在几何和占用层继续关联同一底层资源。它不是新的 Part，也不要求新增顶层本体类型。

安装位置也可以引用同一 Part 上的实体柱 Feature，此时不虚构孔道或端口。源法向、闭合端面和有限壁区分内孔与外柱；有拔模角的锥销保留真实有限边界。功能位置已确认、机制或最少选用数量未确认时，分别保存已知声明和 unknown 条件，不能套用别的接口规则或隐藏已知位置。

孔级作用角色引用稳定的原子孔／Feature 身份，并保留贯穿、承接、定位等功能依据。Interface 的方式可以引用成员池 H，以参数 S⊆H 选择实际成员，结合 MATCH、连接件要求与共同条件产生绑定。不同子集不因此成为新的 Interface 定义，也不强制将整 Part 的不同接口合为一项。

S 等于指定集合、S 包含某个锚点集合、数量范围与成对要求是不同谓词。若只知 AB、CD 两个成立例子，其他集合保持未知；只有来源明确声明完整允许集合时才能用其穷尽过滤。AB、CD 分别成立不证明其并集在同一构型下成立。组合规则注明机械、工程或任务维度及完整性，不把推荐清单当物理禁入规则。

“同侧至少两个相邻孔位”约束本次选择的入口侧和允许邻接关系；相邻不能用列表序号或最近邻自动代替。接口可引用八个孔位，以参数选择一侧及其中成员，不把两侧测量分组或每个双孔子集复制成接口定义。额外选孔仍须满足同一构型、互补结构及连接件条件。

几何阵列本身只证明布局。形成 Interface 假设还须有具体机制、本方及互补角色、有限作用特征和功能来源或可复验功能结构见证。普通裸面、齐孔、有限投影重叠或机制名称不能单独满足这一资格。

### 7.6 装配方案查询

查询固定部件修订、起始配置、机制和连接件范围、已保持关系及适用要求，生成含选孔、对端映射、参与者、共同构型、作用区、路径、状态条件及未决项的方案。刚性模式的全部所选特征共用一个 proper SE(3) 变换；内部活动区域共用一致的 q 与 Frame 生成链，不能逐孔独立配准。

完整连接还原还应说明定位、导向、保持及转矩的作用分工、第三件与允许运动，不以有限面投影替代固定方式。支持资料来自用户、项目推断或厂商通用结构时分别限定证明范围；指出接口漏项不等于确认具体特征的用途。

缺少标准件原始网格时可按有依据的规格补建，固定来源和参数。实际用途或规格未确认的补全示意以 synthetic 身份与未知物料状态展示，不构成已确认实物 Part、BOM 或保持状态。部件对的广相筛查、还原完整性与机械验收分别判断，具体实现见[连接还原](../build/connection-reconstruction.md)。

Build 已有资料中的标准安装关系应随参考 Configuration 交付，标明具体双方孔位、机制、参考位姿、连接件角色及依据。孔壁之间的间隙不能单独否定可由连接件实现的关联；参考对齐复核与实际紧固分开。Simulate 消费已知关系并维护新的试装及接合状态，不负责重新发现原资料已经表达的标准对应。

选择、映射和搜索结果分别保留完整性。对称布局可产生多个旋转对应，后续再检查方向、其他几何、工程与 Task，不以原始参考姿态或特征 ID 任意固定唯一答案。没有找到受支持方案，不等于不存在安装方式。详细消费规则见[装配方案合同说明](assembly-interfaces.md)。

## 8. 具体接口连接与局部状态

### 8.1 连接记录

InterfaceConnection 是可引用的多参与方关联，可包含多条贯穿路径、多个接触或啮合关系。至少有两个端点；外部装配涉及至少两个不同 Part，一个 Part 可以贡献多个端点。

| 结构 | 必须明确的内容 |
| --- | --- |
| 连接身份 | 连接 ID、配置快照、版本及来源性质 |
| `bindings` | 端点键、Part、Interface、方式、角色、所选特征及定义版本 |
| `couplings` | 作用关系键、具体端点或特征、机制与参数、空间条件 |
| `stacks` | 路径键、有序层、贯穿、承压、承接及所属作用关系 |
| 局部状态依据 | 可观测或模拟状态输入、参数、证据及适用位置 |
| 派生判断 | 已检查条件、结果、依赖版本、计算能力与假设 |

`bindings / couplings / stacks` 的键在连接内稳定。螺栓、垫圈、螺母均通过自己的接口参与；仅列在附件清单中不能证明其作用已经成立。

连接存在只表示关联已被表达。对齐中的关联、部分接合、已经完成以及机械成立但任务错误，均可以使用同一结构。

### 8.2 局部状态与整体完成

状态以带作用域的条件谓词表达，例如 `C.p1.thread_engaged`、`C.p1.retaining`、`C.p2.fully_withdrawn`。这些谓词可以同时成立或相互排斥，关系由机制明确规定。

假设某方式要求 p1、p2 两条路径均完成，则：

`complete(C) = complete(C.p1) AND complete(C.p2)`

其他方式可以要求指定子集、计数或条件组合，不统一规定所有参与者的所有状态都必须成立。整体结果由局部条件派生，不能再保存一套可独立改写的完成事实。

状态依赖可来自位姿、接触、锁止件位置、螺纹啮合量、模拟模式参数或现场证据。派生状态不得只引用自己或另一条循环派生状态作为证明。选择理想固定模型可以约束运动，但不能再用这个人为固定的结果反过来证明真实夹紧已完成。

### 8.3 叠层、保持与连通

每条贯穿路径分别描述头下承压、板件、垫圈、螺母等有序层及具体关系。有效啮合按对应区域及适用规格判断，不用包围盒长度相减代替。

连通性由当前已成立且具有相应连接意义的具体 coupling 推导。单纯接触、对齐、候选关联不自动形成装配连接；普通支承是否纳入某种连接图，需明确图的用途和机制语义。

连接 C 中，p1 已形成保持而 p2 尚未插入时，p1 的实际作用继续参与组合和运动判断；p2 的连接件即使已经列入绑定，也不因此被并入物理组合。某条连接不符合任务目标，也不能从当前机械图中删去。

### 8.4 约束随局部状态激活

每条机械约束明确作用框架或特征、约束表达式、激活条件、参数、模型假设和依据。

| 局部状态 | 约束处理 |
| --- | --- |
| 仅对齐 | 不自动生成固定或保持约束 |
| 部分插入 | 按实际机制和选用模型激活导向、接触或间隙条件 |
| 已形成保持但未完成全部要求 | 已成立的保持继续生效，完成判断仍可能不通过 |
| 已锁止或夹紧 | 激活相应约束；若采用理想固定近似，记录其适用范围 |
| 已解锁但未退出 | 解除相应锁止约束，继续检查残余接触、导向和占用 |
| 接到了错误对象但机械作用成立 | 同样激活机械约束，另报任务偏差 |

激活依据不能统一写成 `task_correct=true` 或 `connection_complete=true`。

激活条件为 unknown 时，保留条件约束并报告可动性未决，或在明确假设的分支中分别求解。不能默认不激活后报告确定的自由度，也不能把保守交互限制写成已确认机械约束。

这里判断的是机械作用的激活条件。缺少工程验收证据，不会自动撤销已有充分支持的保持关系。

### 8.5 孔组绑定与并行使用

一次多孔安装可以形成含多条局部路径的连接；两个部件也可以有多处独立连接，不能按 Part 对或孔数唯一化。S 表示本次选定绑定，实际进入、接合、保持与完成分别由各局部状态判断。整体完成只按所选方式的必需项派生，不以选中孔数直接判定。

同一参数化接口可分别用 AB、CD 参与不同连接，继续按实际通道区间、有限作用区、参与者与 SHARE 条件判断并用，不设置全接口统一 capacity=1。具体绑定中的选孔、对端、映射或参与者变化遵循第 3 节连接身份及局部连续规则；Interface 定义身份不随参考对端和子集变化。

同一孔道两侧的安装孔位虽有不同入口身份，共用仍须落到实际区段和参与者判断；不能因孔位 ID 不同绕过冲突。来源标准双孔安装是带上下文的一个已知解，不自动成为其他组合的禁入白名单，也不自动将参考选孔集合写成当前已接合集合。

## 9. 配置、分支与状态来源

### 9.1 快照内容

配置包含部件引用、连接记录、独立放置和运动坐标、实际组成与暴露映射、定义版本、集合覆盖范围、来源与假设。

配置用途与对象域分开。用途可以是来源参考、目标参考、当前模拟、预测、实物观测或假设实验；不能因观察对象是实物，就把其模拟预测当成实物当前状态。

构型快照不自动等同于完整动力学状态。若需要继续仿真，可附 `checkpoint_ref`，按具体后端、版本和冻结模型说明必需的速度、内部状态、历史变量、控制输入或控制器状态、随机状态，以及影响声明恢复保证的缓存。区分“恢复构型”“继续动力学”和“确定性重放”；后两者需要对应能力与复验，不能仅凭恢复 q 宣称无损续算。后端状态字段全集随模型和实现变化，本体不规定一个适用于所有引擎的固定列表。checkpoint 与配置须原子绑定到同一时刻、输入和模型版本。[S15]

参考配置与当前配置可以引用相同模型 Part 的身份，但相互独立保存关系和构型。实物对应通过明确映射建立。跨配置比较须声明对照映射、允许的等价关系及比较范围。

### 9.2 位姿和坐标的权威来源

一份配置明确哪些变量是独立输入、哪些是约束求解结果、哪些来自观测。相同变量不能既由关节坐标独立驱动，又由另一个可写世界位姿独立驱动。

连接保存相对条件，配置保存当前构型；由构型导出的世界位姿可缓存。来源观测、设计约束与求解结果冲突时，保留各自性质并报告残差。

选取一个框架用于坐标表达，不等于把该部件物理固定到世界。界面中的临时拖动锚点、模拟夹具和真实支承分别注明，不能改变任务验收语义。

运动与验收结果须声明所含环境约束。仅为交互设置的拖动锚点不作为保持、固定或任务运动能力的证据；任务明确包含的夹具或支承可参与判断，并保留其作用范围。

### 9.3 尝试、部分变化与假设分支

用户指定一次尝试时，运行时可以形成待评估绑定；只有实际发生的或明确假设的局部效果进入新的当前配置。移动、接触、部分插入已经发生后，即使最终接合失败，也保留相应变化。自动回滚是交互策略，不是本体默认事实。

缺少关键数据或后端能力时，可在带假设的独立分支中演示。分支至少记录父配置、假设条件、影响对象与判断范围。其结果可用于探索，不能回写为已确认机制或实物验收。

恢复历史配置属于场景管理；物理拆卸必须引用实际转换条件。两者不能混用，从而把不可退出的零件通过历史切换假装已经拆下。

### 9.4 求解候选与权威状态的提交规则

模拟过程中区分三类记录：`candidate` 是临时求解或交互构型，`accepted_simulated` 是在明确检查范围内获准提交的配置，`observed` 是对现实的观测主张。候选和界面临时状态不会自动成为权威配置；这是本版的运行时消费契约，不新增执行事件领域模型。FreeCAD 近期的临时状态保存修复也提示了这种分离的必要性，但其修复不等于实现了本节全部规则。[S11]

一次模拟提交至少满足：

1. 父配置和全部定义、几何及后端参数版本与本次求解输入一致。
2. 数值有效，所需约束残差、几何误差及保留关系满足声明检查剖面的阈值。
3. 需要验证的运动段有对应路径覆盖依据；只通过终态检查不称为该段已经可达。
4. 部分进展明确指出起点和已接受的路径前缀，未通过的后段仍为候选或失败诊断。
5. 机械关系、位姿、运动坐标及局部连续性映射作为一致的新快照原子发布；父配置已改变则重新检查，不强行覆盖。

检查剖面须预先列明本次提交必需的条件、范围、几何表示及近似、碰撞过滤、误差阈值和后端能力。缺失的必需检查不能因为没有执行而视为通过，也不能在失败后悄悄缩小范围取得同名通过结论。范围有限的模拟状态可以提交，但其标签和后续消费必须保留该范围，不能升级为更强的物理确认。

验证所用的接触、框架变换、传感器值及派生缓存须刷新或证明对应同一候选构型与时刻；不能把更新后的 q 与上一计算步的残差拼成通过记录。

提交结果保留 `parent_configuration_ref`、操作及参数引用、`validation_profile_ref`、候选与接受构型的区分、已接受区间、所用检查及结果、剩余阻挡或未决原因。区间是否连续成立取决于所声明的解析或碰撞检查能力，不能由采样点数量自动推出。

求解停止原因单独保存。一个残差超标的末次迭代不能未经验证提交；一个达到声明精度的近似结果，也不应只因没有达到数学上的精确收敛而被拒绝。MuJoCo 官方文档描述了数值求解提前终止及诊断机制；PSOP 的提交决定因此使用明确的验收剖面，而非仅使用一个 `converged` 布尔值。[S5]

| 结果 | 配置处理 |
| --- | --- |
| 已确认机械阻挡，前缀通过检查 | 提交已验证前缀，报告后段受阻；任务可能仍未完成 |
| 数值求解停止，末次候选未通过检查 | 不提交该候选；保留诊断和最后已接受状态 |
| 近似解在所声明阈值和覆盖范围内通过 | 可以提交，并保留计算精度与模型依据 |
| 路径能力不支持，但静态终态可表示 | 可保留静态候选或假设分支，不称为已通过该运动达到 |
| 实物观测与模型不一致 | 保存观测及不一致性；不因模型无法解释而删除观测 |

`observed` 表示观测主张，不保证覆盖整机，也不保证没有测量误差。保留实际覆盖对象、时间、不确定性和原始读数；未观测部分不得自动补为已确认。

### 9.5 输入事实、模型假设与求解输出

状态依据区分原始主张、显式仿真假设和派生结果。约束激活引用相应状态依据；求解输出在声明模型下产生构型与残差；验收检查再引用这些结果能实际支持的条件。

禁止的依赖是“假定已经紧固 → 加入理想固定 → 以固定后的姿态证明真实紧固”。允许的计算是接触状态、位姿和活动约束的联立或迭代求解。前者涉及证据自我证明，后者属于已声明模型内的数值求解，二者不混同。

实现可以缓存派生结果或在重编译时保留后端状态，但须按本体依赖规则决定其适用性。MuJoCo 的模型编辑和状态保留能力不自动证明更换连接件后局部身份、载荷或验收证据连续。[S6]

## 10. 当前装配的运动与可达性

### 10.1 按当前关系共同求解

运动判断共同考虑部件内部运动、实际外部连接、环境支承、当前约束模式、限位、相关几何及接触条件。无论连接是否符合任务，已经成立的作用都参与计算。

移动一个部件时，应求解相关部件与活动框架的联动。不得通过只改变显示网格而保持旧接口位姿，制造渲染、碰撞和装配判断之间的不一致。

### 10.2 三种运动结论

| 结论 | 含义 |
| --- | --- |
| 名义运动能力 | 某个运动定义或机制单独允许的坐标变化 |
| 当前局部可动性 | 当前构型和激活约束下，哪些微小变化或方向仍可发生 |
| 有限路径可达性 | 从当前配置到某个构型是否存在满足所声明检查范围的路径 |

剩余自由度属于配置和模型下的派生结果。报告应说明参照与锚定、活动约束、坐标或可动方向、范围、求解状态和假设。自由漂浮组合的整体运动与内部相对运动分别报告。

在规则构型、仅有光滑双边等式约束等适用条件下，可以通过约束雅可比的独立性分析局部可动性；不使用“关节自由度相加再减连接数量”的通用规则。接触、限位和摩擦可能造成单向或状态相关限制，不能强制压成一个永久不变的自由度整数。位置参数的个数也不能直接当成自由度数。[S5]

CAD 中展示单个 Mate 的运动自由度，只能作为局部机制说明；当前整体运动仍须检查其他已建立关系。Onshape 官方文档明确区分忽略其他 Mate 的预览与全部 Mate 的联合求解，本版采取同样的范围区分。[S12]

### 10.3 闭环、碰撞与简化模型

多个连接构成闭环时共同检查，局部关系分别通过不证明整体有解。约束冗余、约束矛盾、奇异构型和求解未收敛分别报告；求解未收敛不等于已证明机械上不可能。

接触检查保留有限区域、接触法向、间隙或允许数值误差。接触例外限定到具体特征和阶段，不能因为两部件需要配合就忽略它们之间的全部碰撞。

采用理想导向、理想固定或其他简化模型时，说明它支持哪些运动结论，以及不支持哪些载荷、摩擦或实物质量结论。软接触后端可能允许模型和数值方法所定义的微小穿透，判断必须使用对应容差与模型范围；不能把所有负间隙都直接解释为实物破坏。[S5]

任务要求的运动区间单独验证。已装完成仍可能因错误干涉而无法完成目标运动；外观吻合、单个关节参数在范围内都不足以证明整段工作运动可达。

## 11. 任务目标、偏差与等价装配

### 11.1 Task 定义可接受配置集合

Task 至少包含适用范围、目标条件、持续约束、条件适用阶段、工程及证据要求、允许的等价或替代规则。目标可以约束某个确切 Part，也可以约束满足规格和能力的某个 Part；两种要求须明确区分。

目标条件直接引用部件、接口、特征、机制和空间条件，或使用有类型的角色变量与数量约束，不要求预先存在某个 InterfaceConnection。任务标签可供显示，但不能替代实际连接事实。

参考配置提供一个目标实例。相同型号互换、替代孔组、镜像结构或不同接口路线是否可接受，由 Task 及适用工程要求决定。比较时可以消除允许的整体刚体变换或身份置换；不得默认所有同型号零件可互换，也不得把一切与参考实例不同的配置判错。

### 11.2 最终目标与持续约束分开

每条任务条件注明何时适用，例如 `always`、`at_acceptance` 或明确的条件阶段。尚未安装时不满足最终目标是正常情况；已经形成与要求冲突的关系则可以产生具体偏差。

持续要求还须声明检查范围为当前配置、转换路径还是过程历史。若 `always` 表示给定区间全过程成立，验收需要相应配置、路径或过程证据；最终快照不能独自证明这一点。该区间一旦存在明确反例，原 `always` 判断保持 false，后续修复不改写过去。

允许纠正后重新验收的任务，必须预先在顶层验收表达式中声明恢复替代分支，或建立具有独立身份与检查范围的新验收实例，并保留原失败记录。若原区间的严格 `always` 仍是同一顶层 AND 的必需项，该次验收就仍然不通过；不能仅增加一次复检，便跳过该 false。普通试错任务不把所有终态要求都设成不可恢复的全过程限制。

| 差异类别 | 含义 | 引导方向 |
| --- | --- | --- |
| `missing` | 必要部件或关系尚未建立，且相关范围已知完整 | 增加所需部件或连接 |
| `incomplete` | 已开始的作用或检查未达到完成条件 | 完成指定局部步骤或检查 |
| `conflicting` | 已有选择、方向、拓扑或运动与明确要求冲突 | 定位冲突，选择可执行的拆改操作 |
| `engineering_violation` | 已知违反当前适用工程要求 | 解释要求，给出符合条件的替换或处理候选 |
| `unknown` | 目标所需事实、证据或计算不足 | 补资料、测量或执行相应检查 |

如果连接集合未声明完整，缺席不能直接产生 `missing`。动作被阻挡、工具不可达或求解未完成作为相应操作的诊断，不能混同为部件装错。

### 11.3 完成判定

任务按自身声明的顶层必需验收表达式和证据范围判断。顶层表达式按第 13 节规则为 true 时，才能在该范围内通过。适用性未决的独立必需项不能当作免检；但某个替代分支已经充分成立时，其他未选分支的未知不必阻止该替代要求通过。不得把任意位置出现 unknown 一律当作全局失败。

不要求与任务无关的全库属性先完备。模拟任务通过的结论须带模型、假设和覆盖范围；实物验收需要与相应实物和实际配置对应的证据。

任务要求输出在区间 Q 内运动时，判定须覆盖其规定的运动性质：仅限位范围、存在某个可达构型，或整个工作路径无阻挡。不能把三者压成同一个 `range` 检查。

## 12. 操作、纠正与引导接口

### 12.1 Operation 的定义

Operation 描述可复用的机械变化或检查。连接类操作引用对应方式的转换和局部关系；重新定位、关节调整及检查使用各自适用的空间和状态条件。

| 内容 | 定义 |
| --- | --- |
| 参与角色 | 部件、接口、连接局部关系及必要工具的绑定要求 |
| 机械前置 | 该变化发生所需的接触、保持、占用、路径和限位条件 |
| 参数 | 有类型、单位与来源的方向、深度、角度等；机械范围与工程、推荐范围分别标注 |
| 转换引用 | 指向相关方式的转换，不复制另一套连接协议 |
| 不变量与影响范围 | 操作中需保留的关系，以及可能被改变的其他局部关系 |
| 预期局部效果 | 可以改变的构型、接触、啮合或模式参数，及其成立条件 |
| 工程与推荐依据 | 适用工艺要求、任务作用及推荐条件，与机械前置分别保存 |
| 完成与验收 | 对应转换的完成标准及本次任务附加检查 |

“不符合任务”可以使操作不被推荐，但不能使一个机械上成立的动作消失。已确认可执行的操作需要相应机械前置有支持；前置未知时可以接受评估请求，或在明确假设下探索，不能直接宣称成功。

### 12.2 纠正按当前配置进行

纠正操作由当前偏差和可用转换导出，不预设用户沿参考顺序执行。下一步可以是安装、松开、退出、转动、重新定位、更换部件或检查。

拆卸不默认是装配的无条件逆过程。铆接、胶接、一次性卡扣或受其他部件阻挡的连接，必须具有适用的解除方式，或报告当前未提供这样的能力。纠正一处时继续检查其他保持关系、随动部件、通道和工具空间。

检查可以不改变机械构型，但会产生新的知识或证据。操作预期效果不等于已经发生的事实；运行时只把实际获得支持的效果写入新配置。

### 12.3 提供给引导器的最小结果

检查器和引导器之间的结果至少携带：

- 当前配置及具体部件、接口、作用关系或路径引用。
- 未满足或冲突的条件、当前值、期望条件、证据与假设范围。
- 差异类别，以及已确认阻挡和未决因素。
- 可选 Operation、具体角色绑定、参数约束及前置判断。
- 预期局部变化和可能影响的其他关系。

例如：“C.p2 已形成夹紧，但绑定的是 S2；任务要求 S1。可评估松开与退出 p2、解除其余保持、换入 S1 的操作。先检查其余保持关系和退出空间。”

本体提供可解释的条件与操作候选。运行时决定提示顺序、交互粒度、是否显示多个方案以及如何记录执行，不把一组未验证候选包装成保证可执行的完整计划。

## 13. 条件表达、判定结果与证据

### 13.1 条件的共同结构

条件依附于实际所属规格、接口方式、空间关系、连接、Operation 或 Task，使用可引用的稳定键。条件表达式具有明确类型和操作数，支持布尔组合、量纲正确的比较、有限集合与计数、空间谓词、连接关系及运动检查。

任意自然语言说明不能代替可执行条件。尚未结构化的说明可以保留为来源或待解析要求，但不得标成计算已经支持。

基础实现要求条件依赖可确定求值，禁止循环自证。几何闭环属于共同约束求解问题，与依靠结论互相证明的条件循环分别处理。

### 13.2 原子结果与合法组合

每个原子条件结果记录 `condition_ref`、`configuration_ref`、`applicability`、`value`、`evaluation_status`、原因、操作数、定义版本、计算或证据方法及其支持引用。适用性由明确 guard 决定；未声明 guard 的条件明确视为无条件适用。

guard 本身消费三值条件：true 对应 applicable，false 对应 not_applicable，unknown 对应适用性未知；其证据与依赖同样接受引用和循环检查。guard 不能由本条件尚未取得的结论循环决定。

`evaluation_status` 描述本条件谓词的求值，不混入 guard 的求值状态。guard 的结果及诊断单独引用。以下表格穷尽原子结果允许的组合，未列组合属于结果结构错误。

本版示例 JSON 将 Truth3 编码为字符串枚举 `"true" / "false" / "unknown"`；不适用时省略 `value`。这与 `tightening_indicator`、集合完整性等原始布尔输入的 JSON true/false 分开。其他编码格式须提供无歧义映射。

| applicability | value | evaluation_status | 条件 |
| --- | --- | --- | --- |
| applicable | true 或 false | evaluated | 当前方法提供充分支持或反证 |
| applicable | unknown | evaluated | 已完成检查，但缺事实、区间不足或证据冲突 |
| applicable | unknown | not_evaluated | 本条件尚未检查，保留原因 |
| applicable | unknown | unsupported | 缺少所需计算能力 |
| applicable | unknown | failed | 本次方法执行失败，不能产生确定结论 |
| not_applicable | 省略 | not_evaluated | guard 已明确为 false，引用其依据 |
| unknown | unknown | not_evaluated | guard 未决，本体谓词不据此获得确定结论 |

已有独立可靠证据可支持 true/false 时，可以生成 `evaluated` 的证据判断；另一种计算方法的失败保留在该方法的诊断中，不把两次方法混成 `unsupported + true`。原始输入的格式或引用错误不伪装成 unknown。

### 13.3 普通三值逻辑

普通 `AND / OR / NOT` 只接受 `true / false / unknown`。不将 `not_applicable`、unsupported 或 failed 当成第四、第五个真假值，也不静默将它们转换成 true。

| A | B | A AND B | A OR B |
| --- | --- | --- | --- |
| true | true | true | true |
| true | false | false | true |
| true | unknown | unknown | true |
| false | true | false | true |
| false | false | false | false |
| false | unknown | false | unknown |
| unknown | true | unknown | true |
| unknown | false | false | unknown |
| unknown | unknown | unknown | unknown |

`NOT true=false`、`NOT false=true`、`NOT unknown=unknown`。对带 guard 的条件取反时保留 guard；不适用不会因取反变成适用且通过。向普通逻辑运算直接传入不适用结果，属于类型或组合错误，应使用下一节的要求聚合。

聚合结果的 `evaluation_status` 描述聚合自身是否完成；不能简单继承子条件最严重的状态。例如一个子项 false、另一个 unsupported，AND 可以正确求得 false，父结果为 evaluated，子项不支持仍作为诊断保留。父聚合成功求得 unknown 也属于 evaluated；只有聚合本身未执行、不支持或失败，才使用相应状态。

### 13.4 带适用条件的要求聚合

要求聚合显式提供集合范围和 `collection_complete`。集合未声明完整时，不把未列条件视为不存在。不适用项表示本要求不参与该次义务，具体意义由下面的聚合类型确定。

**`all_required(items, min_applicable, collection_complete)`：所有适用的必需项成立，并达到明确的适用数量。** `min_applicable` 为必填非负整数，不用隐式的空集通过掩盖要求遗漏。

1. 任一已适用项为 false，结果为 false。
2. 若集合完整，已适用数量加适用性未知数量仍小于 min_applicable，结果为 false。
3. 无上述反证，但存在适用性未知、已适用项的 value 未知，或必需集合不完整，结果为 unknown。
4. 剩余情况下，已适用数量达到 min_applicable 且全部为 true，结果为 true；数量不足为 false。

因此，全部不适用且 min_applicable=1 时为 false；全部不适用且明确声明 min_applicable=0、集合完整时可以为 true，含义仅是当前没有需满足的适用义务，不能据此替代其他任务目标。

**`any_alternative(items, collection_complete)`：至少存在一个适用且成立的方案。**

1. 任一已适用分支为 true，结果为 true，其他未选分支未知不阻断。
2. 尚无成功分支，但有适用性未知、适用分支的 value 未知，或集合不完整，结果为 unknown。
3. 剩余情况下结果为 false，包括全部分支不适用。

聚合自身也可以有独立 guard，按原子适用性约定处理。guard 排除整个要求与其中所有候选恰好不适用是不同情况。

计数、存在性和全称条件按同样原则使用已知数量与未知数量的上下界，并声明以对象、局部作用或独立方案的哪种身份去重；同一事实的多份报告不增加满足者数量。只在完整范围下采用闭世界否定；存在性已有一个充分支持的满足者时，不因其他候选尚未知而否定它。

### 13.5 证据范围与状态更新

来源手册支持要求和工艺，模型计算支持冻结模型中的条件，现场测量支持对应实物和测量范围。照片、量具读数、工具记录和仿真结果分别保留其能支持与不能支持的结论。

证据至少定位到对象、配置或适用时间、来源、测量或计算条件和限制。历史证据可以继续有效，但需要明确哪些依赖未改变；不能无条件复制到替换后的部件或不同连接路径。

派生判断保存依赖版本。依赖变化后重新判断或标记失效，不保留一枚脱离来源的永久“已通过”标签。多个证据在同一条件下冲突时，保留冲突并阻止无依据的完成结论。

| `S1/output_rotation` | 转子相对外壳的内部运动；输出特征随转子变换 |
| `C0 / C1 / C2 / C3` | 分别表示初始服务接口绑定、换件后绑定、seat_a 绑定和 seat_b 绑定 |
| `task/main` | 接受 S1 与 B 的 seat_a 或 seat_b 组合，要求两路径完成，并满足声明的解析运动区间 |

service 在合成模型内可以形成机械保持，但不在任务允许接口集合内。它用于验证“机械接得上、任务接错了”的状态，不通过给错误接口制造虚假的几何冲突来回避误装。

示例使用简化机制 `mechanism/toy_through_clamp`。`held / guided / free` 是有来源的合成模式输入；`tightening_indicator` 是该示例的完成输入，不代表测得扭矩、真实预紧力或螺纹质量。检查器应根据这些输入派生保持、局部完成、连通与任务判断，不从“已经保持住”反推真实紧固。

### 14.2 配置与转换

| 配置 | 实际绑定和局部状态 | 需要得到的结论 |
| --- | --- | --- |
| A0 | C0 连接到 B.service；p1、p2 有保持，只有 p1 满足示例完成条件 | 误接接口可表达，当前保持生效；整体尚未完成 |
| A0u | 解除并退出 p2，p1 保持；尚未更换连接身份 | p1 与 p2 的局部作用独立；p2 连接件不再因绑定列表而自动连入保持图 |
| A1 | p2 用 N3 替换 N2 后重新形成保持；建立 C1，p1 映射为连续 | 父连接身份变化；p1 局部作用连续；p1 相关证据仍逐项复核 |
| A2 | 维持错误服务接口，调整输出坐标 q | 输出特征按内部运动变化，外壳保持；接口任务偏差仍存在 |
| A3 | 解除 p1 保持，p1 仍在导向通道内；p2 继续保持 | 局部解锁不等于所有占用消失，也不等于整体已经分离 |
| A4 | p1 已退出，p2 仍保持 | p1 连接件退出当前保持图；S1 与 B 仍通过 p2 连通 |
| A5 | 解除并退出 p2，将 S1 与连接件重新放置为分离构型 | 保留所有 Part 身份；当前保持图分离，任务表现为缺少所需装配 |
| A6 | 从 A5 形成 C2，使用 B.seat_a，两路径完成 | 在合成解析剖面内通过任务验收 |
| A7 | 从 A5 独立分支形成 C3，使用 B.seat_b，两路径完成 | 替代接口同样通过，不能因与 A6 不同而判错 |

A6、A7 的进入过程保留各自转换引用与合成路径假设。示例没有通用碰撞后端，因此不把这些路径记录称为经过真实 CAD 连续碰撞验证的可达路径。对于实物或更强仿真验收，仍须补齐其任务要求的能力与证据。

### 14.3 局部连续性与证据复核

关键映射为 `(A0u, C0, p1) → (A1, C1, p1)`。两份配置的绑定相同，换件操作影响 p2，并有保持 p1 的合成过程依据。该映射说明 p1 的局部作用连续，不说明 p1 的所有结论都不变。

| 依据 | 新配置中的处理 | 原因 |
| --- | --- | --- |
| p1 的相关几何依据 | 依赖复核通过时可继续支持对应几何判断 | 相应部件、特征与模型定义没有改变 |
| 依赖原整体载荷工况的 p1 判断 | 不能直接复用为当前结论 | p2 替换后的工况依赖已经变化 |
| p2 的旧承接件状态 | 不继承给 N3 | 对象身份与具体绑定已经变化 |
| 原证据记录 | 保留原配置、对象和来源 | 当前不再适用不等于历史记录应被删除或改写 |

检查器必须实际比较声明的依赖，不把 `replaces_ref` 或相同局部键当作一键继承所有证据的开关；该行为待配套代码与反例复验。

本例的工况复核仅检查依赖标识和修订，不计算受力大小或载荷重新分配。几何证据复用也仅指对应特征与修订依据，当前构型的锚点残差仍独立检查。

### 14.4 输入、约束、求值与验收的关系

| 层次 | 示例中的内容 | 可以支持的结论 |
| --- | --- | --- |
| 来源与假设 | 合成几何、刚性区域、运动定义、模式语义、路径假设 | 明确本例的建模前提 |
| 状态输入 | 根框架位姿、q、局部 mode、depth、tightening_indicator | 作为该配置的合成输入，不冒充实物测量 |
| 当前机械关系 | held 激活对应保持；guided 保留适用导向；free 不提供保持 | 当前保持连通及所声明的运动限制 |
| 计算输出 | 框架变换、局部条件、连通分量、残差和依赖差异 | 对冻结输入与有限解析模型的检查结果 |
| 任务判断 | 实际接口是否获准、两路径是否完成、输出区间是否符合要求 | 在明确合成范围内的 task/main 结果 |
| 实物工程验收 | 本例未提供相应对象、工况和现场证据 | 不产生真实预紧力、承载或实物已装好的结论 |

用于数值求解的模式假设始终保留在输出依赖中。若以后增加接触求解器，可以把内部联立求解作为一个计算块；其输出仍不能反过来伪装成独立证明输入假设的原始证据。

### 14.5 受阻、数值候选与历史要求

机器示例需包含三组提交案例：经过限定范围检查的部分前缀、超差末次迭代，以及残差合格但求解器提前停止的近似结果。检查器应根据剖面与候选数值计算是否接受，不仅查看 `converged` 标签。

还需包含不一致的合成观测主张，验证原始观测被保留，并与可接受模拟状态区分。历史用例应验证：原区间已经存在反例时，严格 `always` 保持 false；预先允许的恢复分支或新验收实例可以分别判断，不能改写过去。

### 14.6 配套机器文件与核验方式

提交稿列出的配套材料为 `example.json`、`example.schema.json`、`validate_example.py`、`validation-report.json` 和运行说明 `README.md`。这些文件未随附件提供，当前仓库也没有该示例包，因此本节不提供一条假定文件已经存在的运行命令。材料补齐后，须检查 Schema、业务引用及依赖闭合，独立执行检查器，并核对报告中的输入、工具摘要与实际输出。

示例包拟将基础定义、连接绑定和配置状态分开存储，组合后仍须表达第 8 节的一份具体连接快照。这是序列化安排，不新增装配身份。`transitions`、`commit_cases`、`temporal_cases` 是验证夹具数据，供检查本体消费契约使用，不把它们提升为新的 Plan 或 Execution 领域本体。

### 15.2 后端适配与能力声明

每个导入、导出或求值适配器须给出能力清单，并把转换损失关联到受到影响的条件。

| 声明项 | 最小要求 |
| --- | --- |
| 版本 | 本体剖面、源格式、引擎、适配器和模型版本分别固定 |
| 数值约定 | 长度与角度单位、坐标轴及手性、变换方向、四元数顺序与乘法 |
| 身份映射 | Part、刚性区域、Frame、Feature、实际连接与后端节点的对应；允许多对一或一对多，但保留依据 |
| 几何与接触 | 显示几何、碰撞几何、有限语义区域、网格近似、碰撞过滤、接触模型及误差 |
| 机制 | 支持的关节、连接、模式转换、拆卸、闭环、单向约束及相关边界 |
| 检查能力 | 静态几何、运动学、碰撞、路径、动力学、工程规则及证据检查各自范围 |
| 状态恢复 | 构型恢复、动力学继续、重放保证与必需 checkpoint 内容 |
| 转换损失 | 已保留、近似、忽略、未支持的具体语义及对结论的影响 |

Isaac Lab 3.0 的迁移指南明确将四元数顺序由 WXYZ 改为 XYZW；其后端差异文档也说明同名或相似参数不能保证同一物理含义。因此约定与能力绑定具体版本和适配过程，不能仅填写“支持 Isaac Lab”或“支持 USD”。[S8][S9]

运行时的碰撞过滤、运动学控制、理想固定和临时夹具都可能改变结果，须保留其来源与作用范围。导出成功、场景能打开、网格看似重合不等同于本体语义完整保留。必要语义无法保留时，报告转换损失，并阻止受到影响的确定性验收结论。

### 15.4 完整实现的验收矩阵

下表是完整实现应覆盖的验收要求，不是已经通过的测试清单。参考实现待核验状态见第 15.3 节；几何与动力学用例还需要对应后端、独立场景数据及可复验输入。

| 编号 | 场景 | 必须满足的结果 |
| --- | --- | --- |
| V01 | 同规格两件部件 | 身份、孔和连接引用不混淆 |
| V02 | 机械兼容但接错对象 | 配置结构有效；机械作用保留；任务偏差有具体依据 |
| V03 | 改变任务允许对象 | 只改变相应任务判断，不改变当前物理状态 |
| V04 | 初始分离与普通中间态 | 未满足最终目标不自动报误装 |
| V05 | 同轴但进入方向相反 | 无向同轴条件与有向进入条件分别给出结果 |
| V06 | 共面但区域不重叠 | 共面不能使接触或承压条件自动通过 |
| V07 | 更换相机或整体坐标表达 | 设备参照的左右判断及机械关系保持一致 |
| V08 | 更新活动关节坐标 | 显示、碰撞、接口和特征使用一致的活动框架变换 |
| V09 | 两路径只完成一条 | 局部状态独立，整体按方式汇总，未接合连接件不误入组合 |
| V10 | 松开或解锁但尚未退出 | 保持变化与通道占用变化分别处理 |
| V11 | 失败尝试已有部分位移 | 保留实际达成的局部效果，不写入未发生的成功效果 |
| V12 | 缺关键规格或枚举未完成 | 保留未知和完整性信息，不误报已穷尽且无候选 |
| V13 | 缺路径后端或求解提前停止 | 区分能力缺失、执行失败与有合格候选；不把停止标签伪装成机械反证 |
| V14 | 终态可行但路径受阻 | 终态与路径判断分开，不靠瞬移产生接合 |
| V15 | 错误连接限制输出运动 | 错误连接仍进入约束和碰撞计算，并能解释运动阻挡 |
| V16 | 闭环中局部通过而整体矛盾 | 共同求解或明确报告能力边界，不凭局部通过宣布整体通过 |
| V17 | 替代接口路线满足同一任务 | 允许多个有效配置，保留各自证据和路径 |
| V18 | 更换部件与定义修订 | 旧快照、旧连接与旧证据仍准确解析 |
| V19 | 总成规格实例化两次 | 内部实际部件身份独立，暴露接口解析不复制特征 |
| V20 | 模型成功与实物验收 | 结论保留域、假设和证据范围，不越界确认 |
| V21 | 数值或观测不一致 | 原始观测保留，拟合结果及残差另存 |
| V22 | 工程要求不符合但机械能接合 | 保留机械状态，工程结论不通过，推荐与试错行为分别处理 |
| V23 | 只替换 p2 而 p1 保持 | 新连接身份与 p1 连续性同时正确；连续映射一对一 |
| V24 | 局部绑定不变但工况改变 | 几何依据与载荷依赖分别复核；不复制旧结论 |
| V25 | 同一端点拆下后重新连接 | 标记重新建立，不能继承之前的紧固状态 |
| V26 | 不适用、未知适用性及开放集合 | 严格遵循合法结果表、显式 min_applicable 和聚合规则 |
| V27 | 无支持或执行失败却填 true | 识别为非法结果结构，不进入任务验收 |
| V28 | 只验证前缀或只验证终态 | 提交与可达性结论限定到已验证范围 |
| V29 | 超差末次迭代与合格近似解 | 前者拒绝，后者可按剖面接受；不依赖单一收敛布尔值 |
| V30 | 以固定结果反证紧固 | 拒绝证据循环，同时允许声明模型内的联立求解 |
| V31 | 历史 always 违反后纠正 | 原区间 false 保留；恢复按预先声明分支或新实例判断 |
| V32 | 后端交换与状态恢复 | 约定、近似、能力损失及恢复保证可追溯，不因导出成功宣称语义等价 |

首个可用实现可以采用有限的理想刚体和关节机制，但其交付范围必须明示。每种声称支持的机制，都应覆盖正确装配、误装、部分完成、未知、运动和纠正场景。不能仅播放一条预设正确路线就宣称已经支持交互装配。

### 15.5 真实项目的验收

针对某个开源项目，交付报告至少说明冻结版本、对象识别范围、空间与运动映射、已实现的接口机制、参考配置及允许变化、实际完成的用例、剩余缺项及其影响。

合成案例验证表达和算法行为；真实项目案例验证资料映射与场景还原；实物证据验证现场对应条件。这些结果分别报告，不相互替代。

| 局部保持容易被理解为全部证据可继承 | 历史证据不改写；当前支持按几何、工况、模型等依赖分别复核 |
| 判定类别正确但组合规则不足 | 穷尽原子合法组合；补三值表、guard、N/A 和集合聚合规则 |
| 受阻后的部分进展与计算失败易混用 | 候选、已接受模拟和观测分开；提交依据剖面与已验证范围 |
| “求解未收敛”容易被当成一律拒绝 | 停止原因独立保存；合格近似可接受，未验证末次迭代不可接受 |
| 禁止循环表述容易扩大为禁止联立 | 禁止证据自证，允许已声明模型中的合法接触与约束联立 |
| 构型恢复与动力学续算界限不够明确 | 可选 checkpoint 绑定同刻配置并声明恢复保证 |
| 历史持续要求与纠正后验收易冲突 | 严格 always 保留反例；恢复在任务表达式或新验收实例中明确 |
| 机器例子只有空间片段 | 明确贯穿案例及配套机器文件要求；提交稿声称的实现和报告待提供、待核验 |
| 外部格式转换的含义容易隐失 | 版本、约定、能力和转换损失进入适配器契约 |

迁移须保留旧定义、旧配置和原始证据，逐项映射空间关系、局部键、状态生成方式、判定编码和依赖。旧 parent 字段不能机械复制成 attached_to；旧“success”不能自动转换成机械、工程、任务与完成四类通过；旧连接身份不能通过改 ID 假装完成实际拆卸。

本版不依照历史实验测试数量宣称兼容。实际迁移需检查具体仓库、Schema、字典、实例、导入映射及后端能力。旧项目证据继续作为历史材料，不由本版合成示例补成新的现实事实。
