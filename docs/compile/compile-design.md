# psop-compile v2：语料、训练与模型闭环

> 2026-11-05（Asia/Shanghai）。Compile 是设备工作区内的一种能力，使用统一工作台。旧包内 apps/compile、旧 compile-profile 和静态训练样例合同退出当前目标。真实训练与推理执行器尚未实现。

## 1. 输入与产物

Compile 固定一个 [DKP v2](../architecture/device-knowledge-package.md) 知识快照，并引用原始媒体、场景观测、标注及审核记录。输出独立版本化的任务规程、语料、数据集、实验、模型和评测工件，由同一设备工作区组织。

SOP／任务规程只表达真实设备任务和验收，用于样本制作、审核与覆盖。训练样本、模型回答与指标不写入硬件本体事实，也不把数据集变成规程节点。

本轮只定义产品和数据责任；完整训练工件 Schema、执行 API 与发布合同尚待实现，不能用旧目录结构或 UI 元数据冒充新产物。

## 2. 多模型与训练目标

| 角色 | 候选能力 | 数据与检查重点 |
| --- | --- | --- |
| 部件／目标检测 | YOLO 类检测模型 | 单件与组合视图、框标注、遮挡、真实照片与同源分组 |
| 可观察关系识别 | RelateAnything 类关系模型 | 同一图像中的对象对、实际检测框、关系依据和可见性 |
| 语音转写 | Qwen-ASR 类模型 | 专有词、真实录音、忠实转写及误插入；首轮可使用基础模型与术语提示 |
| 现场帮助 | MiniCPM-V 类多模态模型 | 原图、问题、实际感知预测、回答正确性、证据不足与帮助有效性 |

这些是目标角色，不是已下载或已验证的模型。每次实际运行固定基座、检查点摘要、预／后处理、环境、许可、数据和配置。是否微调 ASR 由实验范围决定，不为凑齐四角色虚构第四类训练记录。

首轮可分别组织检测、关系和帮助三类训练实验；模型组合还需独立端到端评测。一个实验组织多个运行，一个运行可产生多个检查点与普通文件，失败运行允许保留诊断但不能标为可交付模型。

## 3. 场景与多视角语料

Compile 创建数据生成计划，调用与 [Simulate](../simulate/simulate-design.md) 共用的场景／渲染底座。用户也可在 Simulate 中准备部件组合和场景，再将其作为数据候选交给 Compile。

[规范十四视图](canonical-14-views.md) 提供六个正交方向和八个角方向的基础覆盖，适用于有可信几何的部件和组合。图像及原始监督由执行器生成；Compile 管理用途、补充标注、审核、数据划分与数据集发布。十四方向是同一对象的不同观察，不是十四个类别，也不要求推理同时输入十四张图。

数据覆盖还包括装配变化、光照、背景、遮挡、真实误检和实景照片。设备知识关系不能直接当作图像关系标签；来源模型姿态不能自动成为实物已装配真值。未支持的标注通道保持缺失。

## 4. 数据与真值

样本固定设备知识版本、对象与配置、场景、相机、图像、监督、反馈来源和生成／审核记录。人工与 AI 反馈分别登记，合成样本明确其模拟范围。

监督层次遵循[原子特征、参数化接口与装配方案](../architecture/assembly-interfaces.md)：Feature／孔道／槽开口、安装孔位、参考观测、功能规则、标准参考映射、装配方案及局部状态分别标注。Build 的标准双孔对应可作为声明配置内的配对正例，须保留用户说明、几何复核及各自适用范围；不推成唯一合法解。普通相向面、齐孔、旧自动分类和选中集合 S 不直接生成已紧固标签，未列组合不自动作负例。

AB/CD/ABC/ABCD 是参数化方式的可能绑定，不应训练成互斥接口类别。保留完整成员、实际子集、映射、连接件和共同构型，分别记录机械、工程、Task、完成和计算支持状态。对称对应采用有依据的等价标签或明确 Task 差异，不能将单一参考姿态或孔ID排序当唯一真值。合成夹具只证明规则实现，不替代实际设备功能依据。

同 CAD、组合、场景家族的所有视角、增强、相邻帧和正反例同组划分，先确定训练／验证／测试归属再扩展观察，避免泄漏。独立真实现场测试集不参与训练、阈值、提示词或参数调节。

同一孔组的成员重排、旋转对称、不同选孔方案和同源装配变体按数据血缘分组。两侧八个安装孔位继续关联四条底层孔道，不能将同一孔两侧近重复裁片拆入训练与测试而夸大泛化。辅助高亮与拓扑证据不进入真实孔口作用范围标签。

隐藏场景状态只供标签和评测；最终模型输入保持与实际服务一致。SOP 节点、标准答案、隐藏连接和内部求解状态不能因页面选中了它们而传入模型。帮助模型采用实际检测和关系预测，保留误检、漏检和不可用情况。

## 5. 训练、模型与评测

真实训练作业需保存输入锁、起止时间、配置、环境、日志、曲线、检查点和失败原因。模型登记关联源运行、数据版本、依赖与评测，普通报告和图片属于运行文件，不混作模型权重。

Simulate 的模型测试在固定场景中执行已登记模型，输出预测、回放、测试报告和失败候选；Compile 组织同口径比较并决定后续数据和训练版本。单模型及协作链分别测，合成评测与真实评测分开报告。

回流必须形成新的输入版本，不能修改冻结评测来抹掉失败。模型不能取代机械约束验证，也不授权真实硬件动作。

## 6. 统一工作台

同一设备工作区提供语料、训练实验、模型和评测入口，与知识、来源和 Simulate 场景相互定位。当前实现只提供真实空状态和能力位置，不执行训练、加载权重或推理，也不提供虚构曲线、预测或成功运行。

旧 [apps/compile](../../apps/compile/README.md) 静态页面仅为退役视觉参考。新的运行入口是 [统一工作台](../../apps/workbench/README.md)；编排边界见 [psop-compile 技能](../../skills/psop-compile/SKILL.md)。
