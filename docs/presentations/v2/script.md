## 统一案例与叙事

主案例为 **Microduck 舵机更换、安装指导与识别复检**。教学设备 `MD-01`、任务 `MD-SERVO-CHECK-01 / Rev.A`、当前操作 `S03`、目标关节 `J01` 保持同一身份。安装仿真展示部件准备、支架对齐、舵机安装、固定连接和复检的先后；现场入口展示正在安装。识别与复检子任务使用“识别记录已有、复检记录缺失”的教学状态；Runtime 等待任务版本、目标部件和复检依据齐备后才能提交完成。

已有 build 资料包含“单个替换舵机的软件识别”和“软件与传感器逐项检查”，审核状态仍为 proposed / document。三维外形使用 walk 来源 XML / STL 装配，保留部件形状、装配变换与颜色；软件识别任务来自 alpha 资料。EG、图像标注和状态分支为原型或教学设计。部件检测只提供画面位置；软件识别与复检来自对应工具记录；最终机械安装和实机操作需另行验证。

主线为 **设备资料 → 部件与任务知识 → 可执行条件 → 操作与反馈 → 核验留痕 → 经审核的学习与复用**。保留 build / compile / simulate、类 Colored Petri Net EG、Runner / Runtime 分工，以及任务对齐微调与蒸馏。旧机械臂实验和 AR 视频继续作为已有成果证据。

## 第 1 页｜PSOP｜理解设备状态，指导操作与验证

**判断：**设备能力的持续交付，需要把当前对象、操作依据与完成条件连接起来。

**屏幕内容：**理解设备状态、指导正确操作、积累可复用技能。同一设备任务连接 build 的爆炸结构、compile 的任务 EG 概览、simulate 的安装预演与手机现场指导。首页 EG 保留绑定、对齐安装、身份与复检两路核验及条件汇合；当前 token 位于待对齐，后续完成状态为空。细分操作和异常分支在工作台中展开。

**构图：**深色背景共用一张连续主视觉。左侧收窄品牌主张；左上展开来源爆炸结构，右上以 13 个原生 EG 节点呈现关键任务结构，中央偏下放大透明来源模型，突出髋部组件对齐。右下为安装画面与原生 AR 标记组成的手机示例。设备上的方向箭头和手机标记分别注册到实际来源接口与安装示意中的紧固位置。功能名作为短标签，取消四卡片、面板和标题条。

**口径：**使用来源模型渲染；任务标识和观察为教学设定，软件版本与几何配置分别绑定。首页为合并操作的教学概览，身份与复检两路共同决定推进；细化执行规格使用工作台 EG。
