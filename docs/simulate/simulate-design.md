# psop-simulate v2：装配、场景、渲染与模型测试

> 2026-11-06（Asia/Shanghai）。Simulate 是设备工作区中的方案查询、装配、观测与模型测试能力。共享有界选择／刚性孔组匹配可独立查询；权威物理动作、路径、渲染和模型执行仍未接入。旧 core／CMP／PORT／IFC、旧 2.x 世界和 API 不恢复。

## 1. 工作区与输入

设备工作区关联固定的 [DKP v2](../architecture/device-knowledge-package.md) 知识快照、场景配置、模拟会话、渲染批次和测试记录。Simulate 的可变状态保存在包外；它不生成新的 DKP profile，不改写 Build 的来源、证据或知识。

基础装配和场景浏览不依赖先完成 Compile，也不要求已有任务规程或模型。模型测试另行选择实际可用的模型版本。缺项按对象和用途报告，不把可浏览几何自动提升为可操作或可训练。

## 2. 自由装配

### 2.1 参数化方式与方案查询

共同合同见[原子特征、参数化接口与装配方案](../architecture/assembly-interfaces.md)。查询固定 A/B、知识修订、起始配置、机制和连接件范围、已有关系及适用要求，生成带选孔 S、对端映射、共同构型、参与者、局部作用及未决条件的方案。

原子孔保持独立身份，Interface/mode描述机制与组合规则；AB/CD/ABC/ABCD 是参数值，不复制接口定义。完整清单、数量范围、锚点包含、成对依赖及开放集合有不同语义。对称映射保留，所有选孔及相关面共享同一刚性位姿或内部 q；不能逐孔独立对齐。

当前共享查询只评估声明范围的组合与刚性匹配，不执行安装。1.4～1.8 真实 DKP 可直接查询 Build 已发布的孔／实体柱安装位置、已知与未知规则和标准参考映射，固定声明来源及参考配置；这些静态关系不创建运行中的已紧固状态，也不宣称穷尽新构型的安装方式。1.3 或无功能依据的部件继续返回几何与缺项，不能将空结果说成不存在装法。合成定义明确 synthetic，不写回真实 DKP 或推成 Microduck 安装许可。1.6 起的连接审查解释定位、保持、中间件和运动归属；全对广相覆盖不等于已完成机械求解。

1.7 的 pin_hole_fits 只描述共同来源配置下的柱孔有限配合，保留双方身份、插入和间隙；安装定位用途为推断，保持与承载 unknown，参考两成员不定义最少数量或允许子集。外侧 Ø5.5 mm 共轴大洞用途未知。补全件以 usage 区分 reference_connector 与 unverified_alternative：前者是已有参考路径中的未绑定连接件，后者不进入当前保持角色；厂商轴心螺钉／压盖归后一类、默认不显示，不生成 Simulate 已固定标签。旧 1.0～1.6 按冻结合同读取，历史解释不延续为当前固定依据。

推荐方案与自由试装分别表达。用户指定的未列组合可在明确假设的分支评估，不用工程／Task 白名单物理锁死；未实现的路径、弹性或实际作用计算报告未评估，不能靠 ghost 或理想固定完成提交。

### 2.2 权威动作与局部状态

目标交互包括取件、实例化、复制、移动、旋转、组合、连接、解除、内部运动、保存配置、撤销和回放。原始参考装配用于观察，接口能力和当前连接约束决定实际允许的作用；任务错误不撤销已经成立的机械作用。

~~~text
前端选择与 ghost 预览 → 类型化动作请求 → 后台检查声明范围内的约束
→ accepted / rejected / unknown → 原子状态与事件 → 前端采用
~~~

动作执行器负责对象版本、当前状态、幂等、冲突和验证范围。浏览器不直接写矩阵冒充权威提交，Agent 不绕过同一动作与验证通道。显示编组、临时夹持、机械连接和局部保持分别表达。

机械可实现性、工程适用性、任务符合性与完成验收按 [硬件本体 draft.4](../architecture/hardware-ontology.md) 分别判断。精确路径、终态、局部保持、特征、闭环与运动的检查剖面必须明示；不以单一成功状态合并。前缀提交或局部连续性只在对应验证器真实支持后开放。

## 3. 单件、组合与场景观测

场景与渲染底座为 Simulate 交互和 Compile 批量计划共用。可选择单个部件、组合或固定场景，设置参考系、相机、材质、背景、光照、遮挡和随机种子。

渲染批次记录输入 DKP、对象和配置、场景状态、生成器版本、参数、文件摘要与实际支持的监督通道。RGB、目标框、mask、深度、法线、姿态和可见性分别声明能力；来源缺少真实连接依据时不能自动生成“已正确装配”的关系标签。

[规范十四视图](../compile/canonical-14-views.md) 是受控视角覆盖，不等于全部训练语料。材质／背景／遮挡增强和真实现场照片另行组织。模型外形渲染不证明实物外观或工程适用性。

## 4. 与 Compile 的职责分工

| 对象 | 责任 |
| --- | --- |
| 场景状态、相机、几何与渲染执行 | 共用场景运行底座，由 Simulate 提供交互和执行入口 |
| 数据生成计划 | Compile 按模型目标创建，也可从 Simulate 的交互场景提出候选 |
| 图像及原始监督工件 | 执行器生成并保存可复验血缘 |
| 样本用途、补充标注、审核、数据划分与发布 | Compile |
| 模型训练与登记 | Compile |
| 固定场景中的模型执行、回放与失败观察 | Simulate 测试能力 |
| 评测口径、模型比较和后续训练版本 | Compile 与工作区评测记录关联 |

不重复实现三套几何或渲染器。用户在 Simulate 发起视图生成，与 Compile 按计划调用底座使用相同配置和结果合同。产出候选不自动成为可训练数据。

## 5. 模型场景测试

显式选定模型、检查点、输入配置和环境。测试集可以针对单模型，也可以针对检测 → 关系 → 帮助的协作链，记录真实输入、预测、指标、时延、错误和复验条件。

模型只接收目标运行环境可取得的观察。隐藏对象身份、连接答案、求解结果、标准步骤和当前任务节点只供标签及评测，不能暗送模型。辅助输入采用实际预测，覆盖误检、漏检、噪声与缺失；关键证据不可见时保留观察不足。

模型建议不改变物理规则或直接取得状态写入权。场景执行器仍承担动作验证。模拟测试不能替代独立真实现场验证。

## 6. 回流与版本

运行日志、人工纠正、失败和未知结果先形成带来源的候选。审核后生成新的场景、数据集或模型版本；涉及基础设备事实时回到 Build 发布新 DKP。原包、旧场景和旧评测保持原摘要，不原地形成循环自证。

同一场景家族、多视角、增强与相邻帧按组划分；密封测试不用于调提示词、阈值或训练参数。

## 7. 当前状态

当前统一工作台可浏览 DKP 来源模型，并展示装配、视图生成和模型测试的组织位置。源参考位姿、爆炸滑块、透明和剖切均属于浏览状态。

共享参数化选择／刚性孔组查询通过 CLI 运行，保留输入血缘、每阶段覆盖及未决项。工作台的几何页展示逻辑孔、模式及原子／父级参考观测，接口页只展示符合新资格的功能定义。几何观测不再计入 Interface；旧 1.1／1.2 显式标为历史几何、未复评。

v2 权威装配引擎、路径／工程求值、批量监督生成、模型执行和评测回流尚未实现，界面必须标为 unavailable。旧模拟器的 SQLite、API、近似几何和验收记录不作为 v2 完成证据，不提供旧合同降级运行。

执行技能入口见 [psop-simulate](../../skills/psop-simulate/SKILL.md)，状态见 [implementation-status](../../skills/psop-simulate/references/implementation-status.md)。
