## 全件安装过程检查与默认视口播放

本轮在固定 DKP 的 **70 个实例、38 份完整来源网格**上检查全部安装过程。发现旧版不仅存在轴承顺序问题：空间整理同时搬运多件，通用弧线在途中穿过其他部件；类型排序不能反映限形和封闭结构，部分子组合应先在台外预装；客户端重新推测接近方向也会覆盖接口约束。[旧流程复核](evidence/automatic-process-before.json)在 73 步、每步 5 个中间时间点观测到 239 个“步骤／部件对”的新增穿入记录，涉及 41 步；这个数量是采样观测，不是 239 个独立设计缺陷。

新流程从成品反向搜索退出方向和阻挡，倒序生成安装依赖；建立 4 个子组合及嵌套抬高工位，先预装再整组对接。空间整理逐件进行，转运以当前库存的组级包络绕行，在安全高度转向，再沿检查过的路径逆向入座。14 个轴承均引用已发布接口轴线，最后一段不旋转。服务端发布完整路径点，客户端按同一函数重放，取消通用接近弧线。正确但阻挡工序的组合可临时打开，原连接 ID、目标构型、网格及一步历史保留。

完整来源网格的约 **64,298 个表面采样点**参与实体射线检查；来源接触按测得深度单独保留，不将原装过盈或接触直接当作设计错误。默认散件新流程为 95 步、127 秒。[加密回放](evidence/automatic-process-after.json)覆盖 2,274 个中间姿态，[独立真实验收](evidence/automatic-process-real.json)更换时间分数后覆盖 2,279 个姿态，均未观测到新增穿入或台面穿透。两轮均包含每段路径的端点与四分点；采用 2mm 表面采样和 0.4mm 运动观测余量，不是连续刚性碰撞检测的完备证明，也不是通用工程配合阈值。所有真实网格均成功读取，未使用包围盒替代网格。

喙部件、两件喙部软质件及左右脚部件的 5 步限形关系，现有资料仍不足以核定实际装入／保持工艺。内部标记 `reference_handoff`，以显隐交接呈现来源结果，不播放不透明实体穿过障碍，不编造材料应变，不改原始设计。**按用户要求界面不显示待核工艺提示**；来源、未核定条件与力学状态在内部报告保持真实，未改成工程通过。

## 轴承预装顺序与轴向动画修复（前一轮）

原演出按连通图和部件类型排序，结构件／舵机先到终态、轴承后补，且最后一段沿散件来向进入，缺少装入工序。本轮改为先开放轴端与承座，预装所有待装轴承，再让轴承与承座组成刚性子组合接入总成，外壳收尾。预装关系来自与成品姿态一致、明确指定成员的参考配合；方向引用 DKP 环接口的具体轴线成员。抬离、转运及同轴对准后，最后 30% 只沿轴线平移，保持终态朝向；下方入口先绕过支承件进入下侧再向上入座，准备区保留台面间隙。挡住装入的正确连接可在演出中临时打开，最终保留连接 ID，临时打开与错误连接分别记录。

[51 项状态及动画测试](evidence/automatic-bearing-node.tap)全部通过，新增覆盖轴承优先预装、预装单元刚性、正确封闭组合临时打开、轴线缺失拒绝、最后一段同轴且不旋转，以及下方入口转运不穿过支承件。[真实 Microduck 检查](evidence/automatic-bearing-real.json)逐个核对 **14 个轴承**：全部先于主装配，轴线与 DKP 具体成员一致，入口包围盒避开其他待装件并高于台面，装入后随承座整体对接。70 部件、69 条参考连接、一步撤销／重做、重载、重复执行及 DKP 清单不变均通过。默认散件时间线为 82.585 秒，规划约 0.72 秒。

TypeScript、Vite 生产构建及技能格式通过，[13 项浏览器回归](evidence/automatic-bearing-browser.json)全部通过，无跳过、失败或不稳定重试，新增实际预装阶段暂停及截图检查。[原 8780 入口](evidence/automatic-bearing-original-entry.json)从用户方案副本完整播放，确认 14 个轴承预装、一个成品组合，原方案不变，浏览器错误为零。当前资源为 `index-BnEFfHzR.js`、`index-BCRkOLcP.css`，摘要见[本轮记录](evidence/automatic-bearing-summary.json)。实际截图：[轴承预装](../assets/screenshots/simulate-bearing-preassembly-1600.png)、[子组合对接](../assets/screenshots/simulate-bearing-unit-1600.png)、[成品](../assets/screenshots/simulate-bearing-complete-1600.png)。轴向工序及包围盒避让仍不代表完整连续实体路径核定，新增连接继续保留“参考 · 待核”。

浏览器使用真实部件及 API 验收：

- 悬停和取消不修改状态；双击已就绪方式只产生一条连接。提交后局部放大接口，展示整组刚性连接动画，结束恢复原相机位置及观察目标（数值误差小于 1e-10m）；Esc 跳过仍到达已提交终态。

- 鼠标拖拽只保存一个移动步骤；Esc 取消，输入框隔离快捷键，1px 相机平移可见。
- 对象实际空间距离和画面间隙同时满足才自动弹卡片，不要求手动对准接口；空间距离很远时即使投影重叠也不触发。悬停过卡片后连续移远仍立即关闭，主动浏览远处目标后的下一次移动恢复距离关闭。卡片直接固定底边，在 1600×1000、1280×800、999×925、1000×700、900×450 和 854×360 下检查整个外框、底栏、内部滚动、与右侧信息卡不重叠及保存后候选更新。
