# PSOP：设备知识、场景与模型能力

> 2026-11-05（Asia/Shanghai）。本文描述 v2 的产品方向与研发原则，不声明所有目标已经实现。当前工程边界见 [系统设计](architecture/system-design.md)，机械语义见 [硬件本体 draft.4](architecture/hardware-ontology.md)。

PSOP 起源于设备交付后的理解、安装、调试、维护和验收需求。操作者面对具体版本、部件和现场观察，需要知道依据是什么、当前状态能否确认、动作受到什么条件约束，以及什么证据能说明结果。

产品围绕设备建立持续工作区：原始资料进入 Build，形成可追踪知识；Simulate 在明确模型中组织装配、场景、观测和测试；Compile 从真实与合成资料组织语料、训练多个模型并评估效果。统一工作台提供共同入口、对象定位、版本上下文和交互，不为每台设备重新生成业务软件。

## 设备工作区

一个工作区围绕一个设备项目。来源、知识快照、场景、模拟会话、渲染批次、数据集、模型和评测在其中相互引用。设备工作区是长期业务容器；一次构建目录、一个 DKP 和一次实验都是其中的具体对象。

工作台与技能都不能把会话内存当业务权威。作业、发布和纠错记录需要明确输入、版本、输出与失败状态。新结果进入新版本，既有证据与已发布物保持原字节和证明范围。

## 显式与学习能力

显式知识表达实体、接口、连接、配置、条件、运动和验收，并用来源与模型限定结论。机械可实现性、工程适用性、任务符合性及完成分别判断，误装中成立的机械作用仍参与当前状态。

学习模型从有限观察识别对象、关系和语音，并结合问题提供说明、指导、诊断或追问。模型输出不是状态真值、物理授权或任务完成证明。最终帮助模型不读取隐藏场景状态或标准答案，实际硬件操作由人完成。

## 三技能闭环

Build 生产数据型 DKP，统一工作台读取知识与资产。Simulate 和 Compile 消费固定知识版本：前者提供场景运行、渲染和测试，后者管理语料用途、审核、划分、训练与模型发布。Compile 可批量调用同一场景底座；模型回到 Simulate 测试，失败经审核后进入后续数据和模型版本。

训练与评测分别报告单模型和协作链。相同 CAD、场景家族、组合、相邻帧和多视角按组划分，保留独立真实测试。合成可控性不能替代现场效果，真实失败不能靠修改冻结评测消失。

## 开放与证据

开放硬件和机器人是长期协作机会，不意味着厂商私有资料或现场数据必须公开。来源、派生、训练和分发范围随具体材料保留。几何、照片、软件参数和实物观察之间的对应需要证据，名称和外形相似不能代替确认。

构建与展示必须承认缺项。原始外形、参考位姿、模型实例与实物部件分别表达；模型来源中的内部状态不是现实世界事实。能力只在实现、验证和可复验产物共同支持的范围内声明。

## v2 重建

旧 core／CMP／PORT／IFC、旧 DKP v1、包内 App 和旧兼容运行链退出主线。新包以 draft.4 为目标，先实现有界来源模型子集，再逐项扩展机器合同与验证器。当前完整机械求值、模拟装配、批量训练监督、真实训练与模型回测尚未完成。

旧图、静态样例、演示视频和历史测试保留其展示或研究范围，不作为新工具已实现的依据。工程系统的当前入口是 [统一工作台](../apps/workbench/README.md) 和三个 v2 技能说明。
